<h2 class="wp-block-heading">引言：企业最想要的 AI，不是&#8221;会聊天&#8221;，而是&#8221;懂我司&#8221;</h2>

<p class="wp-block-paragraph">通用大模型答不出&#8221;我们公司的报销流程是什么&#8221;&#8221;这款产品的保修条款如何&#8221;，因为它没见过你的内部资料。企业真正的刚需，是把散落在文档、Wiki、工单里的知识，变成一个&#8221;问一句就能答、答得准、可追溯&#8221;的助手。</p>

<p class="wp-block-paragraph"><strong>Dify</strong> 是一个开源的 LLM 应用开发平台，最强点在于：用可视化界面，零代码拼出一个带 RAG（检索增强生成）的知识库问答 Agent，并能一键封装成 API 供业务系统调用。本教程带你从部署到上线走一遍。</p>

<h2 class="wp-block-heading">一、为什么选 Dify 做企业知识库？</h2>

<ul class="wp-block-list">
<li><strong>零代码可视化</strong>：知识库、Prompt、工作流全拖拽，业务同学也能参与。</li>
<li><strong>RAG 开箱即用</strong>：文档切分、向量化、检索、重排一条龙。</li>
<li><strong>多模型兼容</strong>：云端 GPT-5 / Claude / Gemini，本地 Qwen3 / DeepSeek 都能接。</li>
<li><strong>可封装 API</strong>：生成的 Agent 直接暴露为 HTTP 接口，嵌入官网、钉钉、企微。</li>
<li><strong>开源可私有化</strong>：数据留在自己服务器，满足合规。</li>
</ul>

<h2 class="wp-block-heading">二、Step 1：部署 Dify</h2>

<p class="wp-block-paragraph">最省事的是 Docker Compose（需先装 Docker 与 Docker Compose）：</p>

<pre><code class="language-bash">git clone https://github.com/langgenius/dify.git
cd dify/docker
cp .env.example .env
docker compose up -d
</code></pre>

<p class="wp-block-paragraph">启动后访问 <code>http://localhost:80</code>，按引导注册管理员账号。</p>

<blockquote class="is-layout-flow wp-block-quote-is-layout-flow">
<p>生产环境建议：改默认端口、配置反向代理（Nginx + HTTPS）、接对象存储与向量数据库（如 pgvector / Milvus），并定期备份 <code>storage</code> 与数据库卷。</p>
</blockquote>

<h2 class="wp-block-heading">三、Step 2：接入模型供应商</h2>

<p class="wp-block-paragraph">进入「设置 → <a href="https://waynetalk.com/free-llm-api-comparison-2026/">模型供应商</a>」，添加你用的模型：</p>

<ul class="wp-block-list">
<li><strong>云端</strong>：<a href="https://waynetalk.com/544/">填入 OpenAI / Anthropic / Google 的 API Key</a>。</li>
<li><strong>本地</strong>：<a href="https://waynetalk.com/533/">选择 Ollama / OpenAI 兼容端点</a>，填入 <code>http://host.docker.internal:11434/v1</code>，即可用 Qwen3、DeepSeek 等私有模型。</li>
</ul>

<p class="wp-block-paragraph">建议生产用「强模型做生成 + 本地嵌入模型做向量化」的混合方案，兼顾质量与成本。</p>

<h2 class="wp-block-heading">四、Step 3：创建知识库并导入文档</h2>

<ol class="wp-block-list">
<li>左侧「知识库 → 创建知识库」。</li>
<li>上传资料：支持 PDF、Word、Markdown、TXT、网页抓取、Notion 等。</li>
<li>设置索引方式与分段：<br />
   &#8211; <strong>分段模式</strong>：通用选&#8221;自动&#8221;，长文档选&#8221;父子分段&#8221;（父块保上下文、子块保精度）。<br />
   &#8211; <strong>检索方式</strong>：默认&#8221;语义检索&#8221;，混合检索（语义+关键词）更稳。<br />
   &#8211; <strong>Embedding 模型</strong>：选本地 <code>bge-m3</code> / <code>nomic-embed-text</code> 或云端嵌入。</li>
<li>点「保存并处理」，等待向量化完成。</li>
</ol>

<h2 class="wp-block-heading">五、Step 4：编排问答 Agent（Prompt 是关键）</h2>

<p class="wp-block-paragraph">创建「应用 → 聊天助手（含知识库）」，在「编排」里配置：</p>

<pre><code class="language-text"><a href="https://waynetalk.com/538/">系统提示词模板</a>（示例）：
你是我司的<a href="https://waynetalk.com/528/">智能客服助手</a>，只基于【知识库】中的内容回答，
不得编造知识库之外的政策与数据。
回答要求：
1. 先给结论，再给依据（引用资料出处）。
2. 知识库无相关信息时，明确说"暂未收录"，并引导转人工。
3. 涉及金额、期限等数字，务必原样引用，不得估算。
4. 语气专业、简洁、友好。
</code></pre>

<p class="wp-block-paragraph">勾选「知识库」并选择刚建好的库，设置召回数量（如 Top 3–5）与相似度阈值（过低会答非所问）。</p>

<h2 class="wp-block-heading">六、Step 5：加工作流，处理复杂场景</h2>

<p class="wp-block-paragraph">单轮问答不够时，用「工作流」编排多步逻辑。例如&#8221;售前咨询机器人&#8221;：</p>

<ol class="wp-block-list">
<li><strong>分类节点</strong>：判断用户意图（售前/售后/投诉）。</li>
<li><strong>知识库检索</strong>：按意图调用不同资料集。</li>
<li><strong>LLM 节点</strong>：基于检索结果生成回答。</li>
<li><strong>条件分支</strong>：命中&#8221;转人工&#8221;关键词则走工单节点。</li>
<li><strong>回复节点</strong>：返回最终答案。</li>
</ol>

<p class="wp-block-paragraph">全程拖拽，无需写代码，却能实现&#8221;会思考的客服&#8221;。</p>

<h2 class="wp-block-heading">七、Step 6：封装为 API 对外提供</h2>

<p class="wp-block-paragraph">做好应用后，进入「访问 API」<a href="https://waynetalk.com/free-ai-api-no-credit-card/">拿到 Key</a> 与端点：</p>

<pre><code class="language-bash">curl -X POST 'https://你的域名/v1/chat-messages' \
  -H 'Authorization: Bearer app-你的APIKey' \
  -H 'Content-Type: application/json' \
  -d '{
    "inputs": {},
    "query": "我们的年假怎么申请？",
    "response_mode": "blocking",
    "user": "user-123"
  }'
</code></pre>

<p class="wp-block-paragraph">把这个接口嵌进官网「智能客服」、企业微信机器人或内部 Helpdesk，前端无需关心 RAG 细节。</p>

<blockquote class="is-layout-flow wp-block-quote-is-layout-flow">
<p>安全提醒：API Key 务必服务端保管，前端直连会泄露；对 <code>user</code> 字段做鉴权，防止越权访问他人会话。</p>
</blockquote>

<h2 class="wp-block-heading">八、质量保障：让答案&#8221;答得准、可追溯&#8221;</h2>

<ul class="wp-block-list">
<li><strong>引用可见</strong>：开启&#8221;显示引用来源&#8221;，让用户点开看原文，建立信任。</li>
<li><strong>阈值兜底</strong>：相似度低于阈值时直接&#8221;未收录&#8221;，避免幻觉。</li>
<li><strong>人工反馈环</strong>：收集&#8221;点踩&#8221;样本，定期补充文档、微调分段策略。</li>
<li><strong>评测集</strong>：维护 50–100 条真实问答作为回归测试，每次改 Prompt 都跑一遍。</li>
</ul>

<h2 class="wp-block-heading">九、成本与性能优化</h2>

<ul class="wp-block-list">
<li><strong>路由降本</strong>：简单 FAQ 用 Qwen3 小模型，复杂咨询才上 GPT-5 / Claude。</li>
<li><strong>缓存命中</strong>：高频问题加语义缓存，省 token。</li>
<li><strong>分段调优</strong>：分段太大噪声多、太小丢上下文，用评测集反推最优块大小。</li>
<li><strong>重排模型</strong>：接入 rerank 模型（如 bge-reranker）提升 Top 结果精度。</li>
</ul>

<h2 class="wp-block-heading">十、合规与版权提醒</h2>

<ul class="wp-block-list">
<li><strong>数据出境</strong>：使用境外模型 API 时，内部文档可能跨境传输，需评估合规风险；敏感行业优先私有化部署。</li>
<li><strong>版权</strong>：上传的文档需有使用权；对外 answering 时避免泄露未授权 third-party 内容。</li>
<li><strong>可审计</strong>：保留问答日志与知识来源，便于追溯与纠错。</li>
</ul>

<h2 class="wp-block-heading">总结</h2>

<p class="wp-block-paragraph">Dify 把&#8221;企业知识库问答&#8221;从一项需要算法团队的工程，变成业务人员也能搭的可视化应用。核心价值不在炫技，而在三件事：资料可信（RAG）、过程可控（Prompt + 工作流）、接入可复用（API）。把内部知识变成随时可问的 Agent，是 2026 年企业最务实的 AI 落地姿势之一。</p>

<h2 class="wp-block-heading">FAQ</h2>

<p class="wp-block-paragraph"><strong>Q1：文档很多很杂，直接全丢进去就行吗？</strong><br />
不建议。先清洗（去重、去导航噪点、统一格式），再按业务域分多个知识库（如&#8221;产品库&#8221;&#8221;HR 库&#8221;&#8221;IT 库&#8221;），检索时按需调用，准确率和可维护性都更好。</p>

<p class="wp-block-paragraph"><strong>Q2：回答偶尔还是瞎编怎么办？</strong><br />
三个抓手：①提高相似度阈值，低于阈值直接说&#8221;未收录&#8221;；②Prompt 明确&#8221;只基于知识库、不得编造&#8221;；③开启引用展示，让用户能核对原文。幻觉无法清零，但可压到业务可接受范围。</p>

<p class="wp-block-paragraph"><strong>Q3：Dify 和直接用 LangChain 写代码比，怎么选？</strong><br />
要快上线、要业务参与、要可视化运维，选 Dify；要高度定制检索逻辑、自研算子、深度嵌入自有系统，选 LangChain/LlamaIndex 自研。很多团队是&#8221;Dify 做 80% 标准场景，自研补 20% 特殊逻辑&#8221;。</p>
