<h2 class="wp-block-heading">引言：写代码，正在从&#8221;敲键盘&#8221;变成&#8221;下指令&#8221;</h2>

<p class="wp-block-paragraph">2026 年，一个全栈项目从 0 到上线，已经可以主要由人和 AI 协作完成。关键不在于&#8221;AI 替你写了多少行&#8221;，而在于你能否<a href="https://waynetalk.com/538/">把需求讲清楚</a>、把边界划明白、把验证做扎实。</p>

<p class="wp-block-paragraph">本文以 <strong>Cursor</strong>（图形化 AI IDE）和 <strong><a href="https://waynetalk.com/free-api-advanced-whitepro/">Claude Code</a></strong>（终端原生 Agent）为代表，拆解一套可复用的全栈开发工作流：从一句话需求，到可运行的完整交付物。</p>

<h2 class="wp-block-heading">二、Step 1：用自然语言把需求拆清楚</h2>

<p class="wp-block-paragraph">不要一上来就让 AI 写代码。先写一份&#8221;产品简报&#8221;（PRD），这是后续所有 Prompt 的源头。</p>

<pre><code class="language-markdown"># 项目：极简博客系统
## 目标
一个支持 Markdown 写作、标签分类、本地搜索的静态博客生成器。
## 技术栈
- 前端：Vite + React
- 内容：Markdown 文件（仓库内 /content）
- 搜索：客户端模糊检索
## 核心功能
1. 文章列表 + 分页
2. 文章详情（Markdown 渲染 + 代码高亮）
3. 标签筛选
4. 全文搜索框
## 验收标准
- npm run dev 可启动
- 写一篇示例文章能正确渲染
- 搜索能命中标题与正文
</code></pre>

<p class="wp-block-paragraph">把这份简报放进项目根目录的 <code>docs/PRD.md</code>，AI 随时能读。</p>

<h2 class="wp-block-heading">三、Step 2：写好项目&#8221;宪法&#8221;——规则文件</h2>

<p class="wp-block-paragraph">Cursor 用 <code>.cursorrules</code>，Claude Code 用 <code>CLAUDE.md</code>。这是给 AI 的&#8221;团队规范&#8221;，能显著减少反复纠错。</p>

<pre><code class="language-markdown"># CLAUDE.md / .cursorrules
## 技术约束
- 使用 TypeScript，禁止 any
- 组件函数式，优先 hooks
- 样式用 CSS Modules，不引入 UI 框架
## 代码风格
- 命名用 camelCase（组件 PascalCase）
- 每个函数不超过 40 行，过长就拆
- 提交前必须过 ESLint 与类型检查
## 不要做的事
- 不要随意新增依赖
- 不要写未测试的复杂逻辑
- 不要修改我未提及的文件
## 沟通方式
- 改动前先给方案摘要（3 条以内）
- 完成后列出已改文件与验证步骤
</code></pre>

<h2 class="wp-block-heading">四、Step 3：分阶段交付，而不是一次梭哈</h2>

<p class="wp-block-paragraph">把 PRD 拆成可验证的里程碑，每步让 AI 交付一个&#8221;能跑&#8221;的版本：</p>

<ol class="wp-block-list">
<li><strong>脚手架</strong>：生成 Vite + React 工程，跑通空白页。</li>
<li><strong>内容层</strong>：实现 Markdown 读取与渲染。</li>
<li><strong>列表与路由</strong>：文章列表、详情页、标签。</li>
<li><strong>搜索</strong>：客户端检索。</li>
<li><strong>打磨</strong>：加载态、空状态、响应式。</li>
</ol>

<p class="wp-block-paragraph">每完成一步，手动跑一次确认，再进下一步。这样即使某步出错，回滚成本也低。</p>

<h2 class="wp-block-heading">五、Step 4：给 Cursor 的高质量 Prompt 模板</h2>

<p class="wp-block-paragraph">不好的 Prompt：「帮我做个博客。」</p>

<p class="wp-block-paragraph">好的 Prompt：</p>

<pre><code class="language-text">基于 docs/PRD.md，实现"文章列表 + 分页"功能：
- 在 src/pages/List.tsx 新增组件
- 从 /content 读取所有 .md 的 frontmatter（title、date、tags）
- 按 date 倒序展示，每页 10 条
- 顶部有标签筛选（多选）
- 使用 CSS Modules，不新增依赖
完成后告诉我：改了哪些文件、如何本地验证、有无遗留问题。
</code></pre>

<p class="wp-block-paragraph">要点：<strong>引用具体文件、给出约束、要求&#8221;交付清单&#8221;</strong>。AI 越知道边界，产出越可控。</p>

<h2 class="wp-block-heading">六、Step 5：Claude Code 跑长程任务</h2>

<p class="wp-block-paragraph">对于&#8221;跨 20 个文件的大重构&#8221;，交给 Claude Code 在终端后台跑：</p>

<pre><code class="language-bash"># 进入项目目录后启动
claude

# 在交互里下指令
> 重构整个 src/api 层，把 fetch 调用统一封装到 src/lib/http.ts，
> 保留现有函数签名，不破坏外部调用。完成后跑 npm run build 确认通过。
</code></pre>

<p class="wp-block-paragraph">Claude Code 会自己读文件、改代码、跑命令、看报错、再修，形成闭环。你只需在关键节点 review diff。</p>

<h2 class="wp-block-heading">七、Step 6：把验证权拿回自己手里</h2>

<p class="wp-block-paragraph">AI 写的代码，永远要过三关：</p>

<ol class="wp-block-list">
<li><strong>能跑</strong>：<code>npm run build</code> / <code>pytest</code> 通过。</li>
<li><strong>符合意图</strong>：人工走查核心路径（如发一篇文章看渲染）。</li>
<li><strong>不退化</strong>：关键逻辑加测试，避免后续改动破坏。</li>
</ol>

<p class="wp-block-paragraph">Cursor / Claude Code 都能调用测试命令，但&#8221;定义什么叫对&#8221;是你的职责。</p>

<h2 class="wp-block-heading">八、进阶：用 Agent 模式做端到端构建</h2>

<p class="wp-block-paragraph">Cursor 的 Agent 模式、Claude Code 的自主模式，可以接受一个完整目标并自我分解：</p>

<pre><code class="language-text">目标：从零搭建并交付上述博客系统，最终 npm run dev 能打开、
写一篇示例文章可正确渲染、搜索可用。允许自行决定文件结构，
但每完成一个大模块就暂停让我确认。
</code></pre>

<p class="wp-block-paragraph">关键控制点：<strong>设&#8221;检查点&#8221;</strong>，不让它一口气改完所有文件而不让你看。自主 ≠ 失控。</p>

<h2 class="wp-block-heading">十、避坑清单</h2>

<ul class="wp-block-list">
<li><strong>不要盲信&#8221;一次成型&#8221;</strong>：长任务务必设检查点。</li>
<li><strong>规则文件要薄而准</strong>：写太多约束 AI 会顾此失彼。</li>
<li><strong>敏感信息别进 Prompt</strong>：密钥、客户数据不要粘贴给云端模型。</li>
<li><strong>大改动先分支</strong>：<code>git checkout -b ai/feature</code> 再让 AI 改，方便回滚。</li>
<li><strong>版权提醒</strong>：AI 生成的代码片段可能源自训练数据，商用前注意许可证与原创性核查。</li>
</ul>

<h2 class="wp-block-heading">总结</h2>

<p class="wp-block-paragraph">Cursor 与 Claude Code 不是&#8221;更聪明的补全&#8221;，而是&#8221;能执行任务的协作者&#8221;。高效使用的关键，是把工程纪律（PRD、规则文件、分阶段、验证闭环）前置，把 AI 当作需要被管理、被验收的&#8221;初级工程师&#8221;。从 Prompt 到完整交付，差的不是工具，而是你定义目标与质检的能力。</p>

<h2 class="wp-block-heading">FAQ</h2>

<p class="wp-block-paragraph"><strong>Q1：零基础能直接用 Cursor 做项目吗？</strong><br />
能，但建议先懂基础编程概念（变量、函数、HTTP）。AI 能补细节，但&#8221;判断它写得对不对&#8221;需要你至少有读代码的能力。把它当加速器，而不是替代学习。</p>

<p class="wp-block-paragraph"><strong>Q2：Cursor 和 Claude Code 会泄露我的代码吗？</strong><br />
云端模型处理的内容会经服务商。敏感代码请用<a href="https://waynetalk.com/533/">本地模型（Ollama + 私有部署）</a>或企业版/自托管方案，并在团队规范里明确&#8221;什么能发、什么不能发&#8221;。</p>

<p class="wp-block-paragraph"><strong>Q3：AI 写的项目能直接上线商用吗？</strong><br />
技术上可以，但需做三件事：人工安全审查（防注入、鉴权）、许可证核查（依赖与生成代码的版权）、性能与监控兜底。AI 加速的是&#8221;写出来&#8221;，&#8221;负责任地发布&#8221;仍靠人。</p>
