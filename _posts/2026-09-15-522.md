<p class="wp-block-paragraph">如果你还在用 SaaS 版 n8n 受限于执行次数、节点数量，或者担心敏感业务数据出境，那么把 n8n 部署到自己服务器上就是 2026 年最值得做的一件事。本文带你从一台干净的 Linux 服务器出发，一步步完成 <strong>n8n 部署</strong>：用 Docker Compose 编排服务、用 Nginx 做<a href="https://waynetalk.com/frp-ssl-ddns-raspberry-guide/">反向代理</a>并配置 HTTPS、用 Postgres 替代默认的 SQLite 实现数据持久化。整套方案可平滑过渡到<a href="https://waynetalk.com/531/">生产环境</a>。</p>

<h2 class="wp-block-heading">为什么要用 Postgres 而不是默认 SQLite</h2>

<p class="wp-block-paragraph">n8n 默认使用 SQLite 存储工作流与执行记录，单机演示没问题，但一旦遇到并发执行、执行记录暴涨或需要备份迁移，SQLite 就成了瓶颈。对比一下：</p>

<figure class="wp-block-table"><table>
<thead>
<tr>
<th>维度</th>
<th>SQLite（默认）</th>
<th>Postgres</th>
</tr>
</thead>
<tbody>
<tr>
<td>并发写入</td>
<td>单写锁，易阻塞</td>
<td>MVCC，支持高并发</td>
</tr>
<tr>
<td>数据备份</td>
<td>文件拷贝，需停机</td>
<td>逻辑/物理备份，热备</td>
</tr>
<tr>
<td>执行历史清理</td>
<td>手动删文件</td>
<td><code>VACUUM</code> + 定时任务</td>
</tr>
<tr>
<td>横向扩展</td>
<td>不支持</td>
<td>可配合队列模式 Worker</td>
</tr>
</tbody>
</table></figure>

<p class="wp-block-paragraph">结论：只要你的 n8n 要承担真实业务，Postgres 是必选项。</p>

<h2 class="wp-block-heading">环境准备</h2>

<ul class="wp-block-list">
<li>一台 <a href="https://waynetalk.com/542/">Linux 服务器</a>（推荐 2C4G 起步，本文以 Ubuntu 22.04/24.04 为例）</li>
<li>已安装 Docker Engine 24.x 与 Docker Compose v2</li>
<li>一个已解析到服务器 IP 的<a href="https://waynetalk.com/221/">域名</a>（例如 <code>n8n.example.com</code>）</li>
<li>开放 80/443 端口</li>
</ul>

<pre><code class="language-bash"># 验证 Docker 与 Compose
docker --version
docker compose version
</code></pre>

<h2 class="wp-block-heading">第一步：创建目录结构与环境变量</h2>

<p class="wp-block-paragraph">建议把所有配置集中在一个目录，便于版本管理：</p>

<pre><code class="language-bash">mkdir -p /opt/n8n/{postgres,nginx,certs}
cd /opt/n8n
</code></pre>

<p class="wp-block-paragraph">创建 <code>.env</code> 文件，集中管理敏感配置（不要提交到公网仓库）：</p>

<pre><code class="language-dotenv"># 基础域名与端口
DOMAIN_NAME=n8n.example.com
N8N_PORT=5678

# Postgres 凭据（请替换为强随机值）
POSTGRES_USER=n8n
POSTGRES_PASSWORD=CHANGE_ME_STRONG_PASSWORD
POSTGRES_DB=n8n
POSTGRES_PORT=5432

# n8n 加密密钥（生成方式见下方命令）
N8N_ENCRYPTION_KEY=REPLACE_WITH_GENERATED_KEY

# 时区
GENERIC_TIMEZONE=Asia/Shanghai
TZ=Asia/Shanghai
</code></pre>

<p class="wp-block-paragraph">生成强随机加密密钥（n8n 用它加密凭据）：</p>

<pre><code class="language-bash">openssl rand -base64 48
</code></pre>

<p class="wp-block-paragraph">把输出结果填到 <code>N8N_ENCRYPTION_KEY</code>。</p>

<h2 class="wp-block-heading">第二步：编写 docker-compose.yml</h2>

<p class="wp-block-paragraph">这是整套部署的核心。我们用 <code>n8nio/n8n</code> 官方镜像（截至 2026 年稳定为 1.x 及以上版本），搭配 <code>postgres:16</code> 与 <code>nginx:stable</code>。</p>

<pre><code class="language-yaml">version: "3.8"

services:
  postgres:
    image: postgres:16-alpine
    restart: unless-stopped
    environment:
      POSTGRES_USER: <span class="katex math inline">{POSTGRES_USER}
      POSTGRES_PASSWORD:</span>{POSTGRES_PASSWORD}
      POSTGRES_DB: <span class="katex math inline">{POSTGRES_DB}
    volumes:
      - ./postgres:/var/lib/postgresql/data
    healthcheck:
      test: ["CMD-SHELL", "pg_isready -U</span>{POSTGRES_USER}"]
      interval: 10s
      timeout: 5s
      retries: 5

  n8n:
    image: n8nio/n8n:latest
    restart: unless-stopped
    depends_on:
      postgres:
        condition: service_healthy
    ports:
      - "127.0.0.1:<span class="katex math inline">{N8N_PORT}:5678"
    environment:
      # 基础配置
      - N8N_PORT=5678
      - N8N_PROTOCOL=https
      - N8N_HOST=</span>{DOMAIN_NAME}
      - WEBHOOK_URL=https://<span class="katex math inline">{DOMAIN_NAME}/
      - GENERIC_TIMEZONE=</span>{GENERIC_TIMEZONE}
      - TZ=<span class="katex math inline">{TZ}
      # 持久化数据库
      - DB_TYPE=postgresdb
      - DB_POSTGRESDB_HOST=postgres
      - DB_POSTGRESDB_PORT=</span>{POSTGRES_PORT}
      - DB_POSTGRESDB_DATABASE=<span class="katex math inline">{POSTGRES_DB}
      - DB_POSTGRESDB_USER=</span>{POSTGRES_USER}
      - DB_POSTGRESDB_PASSWORD=<span class="katex math inline">{POSTGRES_PASSWORD}
      # 安全
      - N8N_ENCRYPTION_KEY=</span>{N8N_ENCRYPTION_KEY}
      - N8N_SECURE_COOKIE=true
      - N8N_BASIC_AUTH=false
    volumes:
      - ./n8n_data:/home/node/.n8n
    healthcheck:
      test: ["CMD", "wget", "--quiet", "--tries=1", "--spider", "http://localhost:5678/healthz"]
      interval: 30s
      timeout: 10s
      retries: 3

  nginx:
    image: nginx:stable
    restart: unless-stopped
    depends_on:
      - n8n
    ports:
      - "80:80"
      - "443:443"
    volumes:
      - ./nginx/conf.d:/etc/nginx/conf.d:ro
      - ./certs:/etc/nginx/certs:ro
</code></pre>

<p class="wp-block-paragraph">注意 <code>ports</code> 中 n8n 只监听 <code>127.0.0.1</code>，由同机 Nginx 反代，避免裸端口暴露。</p>

<h2 class="wp-block-heading">第三步：配置 Nginx 反向代理与 HTTPS</h2>

<p class="wp-block-paragraph">申请证书（使用 acme.sh 或 certbot，此处以 certbot 为例）：</p>

<pre><code class="language-bash">sudo apt install -y certbot
sudo certbot certonly --standalone -d n8n.example.com
# 证书会落在 /etc/letsencrypt/live/n8n.example.com/
cp /etc/letsencrypt/live/n8n.example.com/fullchain.pem ./certs/
cp /etc/letsencrypt/live/n8n.example.com/privkey.pem ./certs/
</code></pre>

<p class="wp-block-paragraph">创建 <code>nginx/conf.d/n8n.conf</code>：</p>

<pre><code class="language-nginx">server {
    listen 80;
    server_name n8n.example.com;
    # HTTP 强制跳转 HTTPS
    location / {
        return 301 https://<span class="katex math inline">host</span>request_uri;
    }
}

server {
    listen 443 ssl http2;
    server_name n8n.example.com;

    ssl_certificate     /etc/nginx/certs/fullchain.pem;
    ssl_certificate_key /etc/nginx/certs/privkey.pem;
    ssl_protocols       TLSv1.2 TLSv1.3;
    ssl_ciphers         HIGH:!aNULL:!MD5;

    client_max_body_size 50M;

    location / {
        proxy_pass http://n8n:5678;
        proxy_set_header Host <span class="katex math inline">host;
        proxy_set_header X-Real-IP</span>remote_addr;
        proxy_set_header X-Forwarded-For <span class="katex math inline">proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto</span>scheme;

        # WebSocket 支持（n8n 实时日志需要）
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection "upgrade";
        proxy_read_timeout 86400;
    }
}
</code></pre>

<blockquote class="is-layout-flow wp-block-quote-is-layout-flow">
<p>关键点：<code>X-Forwarded-Proto</code> 与 WebSocket 头必须配置，否则 n8n 的编辑器实时日志会断连。</p>
</blockquote>

<h2 class="wp-block-heading">第四步：启动并验证</h2>

<pre><code class="language-bash">docker compose up -d
docker compose ps
</code></pre>

<p class="wp-block-paragraph">打开 <code>https://n8n.example.com</code>，首次访问会要求创建 Owner 账号。登录后进入 <strong>Settings → About</strong>，确认 <code>Database: postgresdb</code>，说明持久化已生效。</p>

<p class="wp-block-paragraph">验证 Postgres 连接数：</p>

<pre><code class="language-bash">docker compose exec postgres psql -U n8n -c "\dt"
</code></pre>

<p class="wp-block-paragraph">能看到 <code>n8n</code>.<code>public</code> 下的多张表即代表迁移成功。</p>

<h2 class="wp-block-heading">第五步：迁移默认 SQLite 数据（可选）</h2>

<p class="wp-block-paragraph">若你之前用的是 SQLite，n8n 官方提供迁移命令：</p>

<pre><code class="language-bash">docker compose exec n8n n8n db:revert
</code></pre>

<p class="wp-block-paragraph">不过更稳妥的做法是全新部署后重新导入工作流 JSON。生产环境建议直接以 Postgres 起步。</p>

<h2 class="wp-block-heading">第六步：安全加固清单</h2>

<ol class="wp-block-list">
<li><strong>开启 2FA</strong>：Settings → Personal → Two-Factor Authentication。</li>
<li><strong>限制来源 IP</strong>：在 Nginx 加 <code>allow 1.2.3.4; deny all;</code>。</li>
<li><strong>执行数据保留</strong>：设置 <code>EXECUTIONS_DATA_PRUNE=true</code> 与 <code>EXECUTIONS_DATA_MAX_AGE=168</code>（单位小时，保留 7 天）。</li>
<li><strong>定期备份</strong>：</li>
</ol>

<pre><code class="language-bash"># 数据库逻辑备份
docker compose exec -t postgres pg_dump -U n8n n8n > backup_<span class="katex math inline">(date +%F).sql
# 卷备份
tar czf n8n_data_</span>(date +%F).tgz ./n8n_data
</code></pre>

<h2 class="wp-block-heading">常见问题排查</h2>

<ul class="wp-block-list">
<li><strong>页面一直转圈/WebSocket 报错</strong>：大概率是反代没配 <code>Upgrade</code> 头，回到第三步检查 Nginx 配置。</li>
<li><strong>Webhook 收不到</strong>：确认 <code>WEBHOOK_URL</code> 与公网域名一致，且防火墙放行 443。</li>
<li><strong>Postgres 连不上</strong>：检查 <code>depends_on</code> 的 <code>service_healthy</code> 条件是否生效，以及密码是否有特殊字符需 URL 编码。</li>
</ul>

<h2 class="wp-block-heading">总结</h2>

<p class="wp-block-paragraph">通过 Docker Compose + Postgres + Nginx 反代这套组合，你拥有了一个数据自持、可 HTTPS 访问、易于备份的 n8n 私有化实例。后续所有自动化工作流都可以跑在这台机器上，不再受 SaaS 额度限制。</p>

<h2 class="wp-block-heading">FAQ</h2>

<p class="wp-block-paragraph"><strong>Q1：1 核 2G 的服务器能跑 n8n + Postgres 吗？</strong><br />
可以，但仅适合个人低频使用。Postgres 空闲约占用 50–80MB，n8n 主进程约 200MB，建议至少 2C4G 以保证多工作流并发时不 OOM。</p>

<p class="wp-block-paragraph"><strong>Q2：能不能不加 Nginx，直接用 n8n 的 HTTPS？</strong><br />
n8n 自身不推荐直接处理 TLS，建议统一由反代层终结证书，这样证书续期、多应用复用都更方便。</p>

<p class="wp-block-paragraph"><strong>Q3：执行记录会无限增长吗？</strong><br />
默认不清理。请配置 <code>EXECUTIONS_DATA_PRUNE=true</code> 与 <code>EXECUTIONS_DATA_MAX_AGE</code>，由 n8n 自动清理旧执行数据，避免 Postgres 膨胀。</p>
