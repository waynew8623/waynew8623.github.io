<p class="wp-block-paragraph">做个人项目、side project、毕业设计，第一步往往是：&#8221;<a href="https://waynetalk.com/free-database-github-student-pack/">数据库用啥？</a>&#8220;付费方案动辄几十刀起步，对个人开发者不友好。所幸 2026 年仍有几款高质量的托管数据库提供免费层。但局势在变——<strong>最需要注意的是：PlanetScale 早已取消免费档</strong>，旧文章里的&#8221;PlanetScale 免费 5GB&#8221;已是过时信息。</p>

<p class="wp-block-paragraph">本文带你厘清三家的真实免费现状，并给出可落地的选型建议。</p>

<h2 class="wp-block-heading">一、重要更正：PlanetScale 已无免费层</h2>

<p class="wp-block-paragraph">先说结论，避免你踩坑：</p>

<ul class="wp-block-list">
<li><strong>PlanetScale 在 2024 年 4 月就移除了 Hobby 免费层</strong>，目前官网只提供付费方案（入门约数十美元/月起，具体以官网为准）。</li>
<li>它基于 Vitess（MySQL），以&#8221;数据库分支（branch）、零停机 schema 变更&#8221;著称，技术很优秀，但<strong>对个人白嫖已不友好</strong>。</li>
<li>旧教程里&#8221;免费 5GB 存储、每月十亿次读取&#8221;的描述<strong>已不适用</strong>，请勿据此选型。</li>
</ul>

<blockquote class="is-layout-flow wp-block-quote-is-layout-flow">
<p>如果你是因为&#8221;PlanetScale 免费&#8221;点进本文，请直接看第三节的替代方案（Neon / Supabase / Turso），它们才是 2026 年仍有免费层的选手。</p>
</blockquote>

<h2 class="wp-block-heading">二、Supabase：一站式后端平台（有免费层）</h2>

<h3 class="wp-block-heading">优点</h3>

<ul class="wp-block-list">
<li><strong>开箱即用</strong>：DB + 登录 + 文件 + 实时订阅 + 向量（pgvector）一套搞定。</li>
<li><strong>SQL 原生</strong>：就是 PostgreSQL，ORM、SQL 客户端通用，迁移容易。</li>
<li><strong>RLS 行级安全</strong>：内置权限模型，适合做多用户应用。</li>
</ul>

<h3 class="wp-block-heading">实测感受</h3>

<p class="wp-block-paragraph">适合&#8221;想要完整后端、不想自己拼服务&#8221;的个人开发者。一个免费项目就能跑起带登录的小应用。存储 500MB 对个人项目够用，但注意免费项目闲置会被暂停，需手动恢复或保持活跃。</p>

  for select using (auth.uid() = user_id);
</code></pre>

<h3 class="wp-block-heading">优点</h3>

<ul class="wp-block-list">
<li><strong>闲置不花钱</strong>：没有流量时计算自动归零，适合访问不规律的 side project。</li>
<li><strong>分支即复制</strong>：为每个 PR 拉一个数据库分支做预览环境，体验极佳。</li>
<li><strong>原生 Postgres</strong>：兼容生态，迁移平滑。</li>
</ul>

<h3 class="wp-block-heading">实测感受</h3>

<p class="wp-block-paragraph">适合&#8221;Serverless 部署（Vercel / <a href="https://waynetalk.com/238/">Cloudflare Workers</a> / 函数）&#8221;的场景，数据库随应用一起按量。0.5GB 存储偏小，数据增长需升付费；但开发/预览环境几乎零成本。</p>

<h3 class="wp-block-heading">选型口诀</h3>

<ul class="wp-block-list">
<li><strong>要&#8221;数据库 + 登录 + 存储&#8221;一条龙</strong> → Supabase。</li>
<li><strong>要&#8221;Serverless + 分支预览 + 闲置零成本&#8221;</strong> → Neon。</li>
<li><strong>只认 MySQL 且预算充足</strong> → 考虑 PlanetScale（付费）；否则看下面的替代。</li>
</ul>

<h2 class="wp-block-heading">五、替代与补充（同样有免费层）</h2>

<ul class="wp-block-list">
<li><strong>Turso（libSQL/SQLite 边缘）</strong>：免费档慷慨（多库、数 GB 存储、海量读取），适合读多、边缘部署的内容站/API。非 Postgres，技术栈需匹配。</li>
<li><strong>MongoDB Atlas（M0）</strong>：约 512MB 共享集群，文档型数据库免费档。</li>
<li><strong>Firebase Firestore</strong>：免费档适合移动端/实时场景。</li>
<li><strong>Cloudflare D1</strong>：SQLite on Workers，绑定 Cloudflare 生态，轻量免费。</li>
</ul>

<h2 class="wp-block-heading">七、FAQ</h2>

<p class="wp-block-paragraph"><strong>Q1：PlanetScale 还能白嫖吗？</strong><br />
A：不能，免费层已于 2024 年移除。需要 MySQL 且想免费，请评估 Turso（SQLite）或<a href="https://waynetalk.com/756/">自托管 MySQL</a>；坚持 PlanetScale 则需付费。</p>

<p class="wp-block-paragraph"><strong>Q2：Supabase 和 Neon 怎么二选一？</strong><br />
A：想要 Auth/Storage/Realtime 一体选 Supabase；想要 Serverless 缩容零、分支预览选 Neon。两者底层都是 Postgres，后期切换成本可控。</p>

<p class="wp-block-paragraph"><strong>Q3：免费档会被突然清空数据吗？</strong><br />
A：正常不会，但闲置暂停、条款变更、额度超限都可能影响可用性。重要数据自己备份，别把免费档当唯一存储。</p>

<h2 class="wp-block-heading">总结</h2>

<p class="wp-block-paragraph">2026 年个人项目后端选型，真正的免费层选手是 <strong>Supabase</strong> 与 <strong>Neon</strong>（以及 Turso、D1 等）。<strong>PlanetScale 已无免费档</strong>，请勿被旧教程误导。一句话建议：全栈小应用上 Supabase，Serverless 预览上 Neon，极简边缘内容站上 Turso/D1。无论选哪个，<a href="https://waynetalk.com/519/">记得备份</a>——免费的东西，最贵的代价是&#8221;以为它永远在&#8221;。</p>
