<h2 class="wp-block-heading">引言：为什么 AI 需要一套&#8221;通用插头&#8221;？</h2>

<p class="wp-block-paragraph">早期让 AI 调工具，每个应用都要为每个模型写一套适配：A 模型的插件、B 平台的连接器，N×M 的集成灾难。2024 年 Anthropic 提出 <strong>MCP（Model Context Protocol，模型上下文协议）</strong>，目标是做 AI 世界的&#8221;USB-C&#8221;——一套标准，让任意模型连任意工具/数据源。</p>

<p class="wp-block-paragraph">到 2026 年，MCP 已成为<a href="https://waynetalk.com/541/">Agent 生态</a>的事实标准：<a href="https://waynetalk.com/532/">Claude、GPT-5 系列</a>、众多 IDE 与框架都支持它。本文讲清它是什么、怎么跑、怎么自己写一个 Server，把&#8221;AI 操作你电脑上的文件与软件&#8221;变成现实。</p>

<h2 class="wp-block-heading">一、MCP 解决什么问题？</h2>

<p class="wp-block-paragraph">没有 MCP 时：</p>

<ul class="wp-block-list">
<li>想让 AI 读本地文件，要专门写代码接某个客户端；</li>
<li>换一个模型，集成得重写；</li>
<li>工具和数据源各自为政，无法复用。</li>
</ul>

<p class="wp-block-paragraph">MCP 做了三件事：</p>

<ol class="wp-block-list">
<li><strong>统一协议</strong>：工具、数据源都用同一套消息格式（基于 JSON-RPC 2.0）。</li>
<li><strong>解耦</strong>：模型侧（Host/Client）与工具侧（Server）独立演进，互不绑架。</li>
<li><strong>即插即用</strong>：一个 MCP Server 写好，任何支持 MCP 的客户端都能直接用。</li>
</ol>

<h2 class="wp-block-heading">二、核心架构</h2>

<pre><code class="language-text">┌─────────────┐         ┌──────────────┐        ┌─────────────┐
│  Host       │  MCP    │  MCP Server  │ 读/写  │  本地资源   │
│ (如 Claude   │ ◄──────►│ (工具提供方) │ ◄─────►│ 文件/数据库 │
│  Desktop/    │ 协议    │ 提供 Tools / │        │ /API        │
│  IDE)        │         │ Resources / │        └─────────────┘
└─────────────┘         │ Prompts     │
                        └──────────────┘
</code></pre>

<p class="wp-block-paragraph">三个关键角色：</p>

<ul class="wp-block-list">
<li><strong>Host（宿主）</strong>：用户直接用的 AI 应用（Claude Desktop、Cursor、VS Code 插件等）。</li>
<li><strong>Client（客户端）</strong>：Host 内与某个 Server 维持 1:1 连接的组件。</li>
<li><strong>Server（服务端）</strong>：暴露能力的程序，提供三类原语：</li>
<li><strong>Tools（工具）</strong>：可被执行的函数（如&#8221;读文件&#8221;&#8221;发邮件&#8221;&#8221;查数据库&#8221;）。</li>
<li><strong>Resources（资源）</strong>：可读取的数据（如文件内容、API 响应）。</li>
<li><strong><a href="https://waynetalk.com/538/">Prompts（提示词模板）</a></strong>：预置的可复用指令。</li>
</ul>

<p class="wp-block-paragraph">传输方式：<strong>stdio</strong>（本地进程间，最常用、最安全）或 <strong>HTTP/SSE</strong>（远程 Server）。</p>

<h2 class="wp-block-heading">三、MCP 通信长什么样？</h2>

<p class="wp-block-paragraph">基于 JSON-RPC。客户端先 <code>initialize</code> 握手，再 <code>list_tools</code> 发现能力，然后 <code>call_tool</code> 执行：</p>

<pre><code class="language-json">// 客户端 → 服务端：列出工具
{ "jsonrpc": "2.0", "id": 1, "method": "tools/list", "params": {} }

// 服务端 → 客户端：返回工具定义
{
  "jsonrpc": "2.0", "id": 1,
  "result": {
    "tools": [
      { "name": "read_file",
        "description": "读取本地文件内容",
        "inputSchema": {
          "type": "object",
          "properties": { "path": { "type": "string" } },
          "required": ["path"]
        }
      }
    ]
  }
}
</code></pre>

<p class="wp-block-paragraph">模型看到 <code>read_file</code> 的定义后，若需要，便生成调用参数，由 Host 执行并把结果回灌给模型。</p>

<h2 class="wp-block-heading">四、Step 1：运行一个现成 MCP Server</h2>

<p class="wp-block-paragraph">以官方文件系统 Server 为例（需 Node.js）：</p>

<pre><code class="language-bash"># 在支持 MCP 的客户端配置中添加（以 Claude Desktop 配置为例）
# 编辑配置文件 claude_desktop_config.json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/你/允许访问的目录"
      ]
    }
  }
}
</code></pre>

<p class="wp-block-paragraph">重启客户端后，AI 就能在你授权的目录里读写了——<strong>注意：只能访问你显式列出的路径</strong>，这是 MCP 的安全地基。</p>

<h2 class="wp-block-heading">五、Step 2：自己写一个 MCP Server（Python）</h2>

<p class="wp-block-paragraph">用官方 SDK 写一个&#8221;读取本地 Markdown 标题&#8221;的工具：</p>

<pre><code class="language-python"># server.py
from mcp.server.fastmcp import FastMCP
import re, os

mcp = FastMCP("md-tools")

@mcp.tool()
def list_md_headings(path: str) -> list:
    """读取 Markdown 文件，返回所有 H1-H3 标题列表。"""
    if not os.path.isfile(path):
        return ["错误：文件不存在"]
    with open(path, encoding="utf-8") as f:
        text = f.read()
    headings = re.findall(r'^#{1,3}\s+(.+)$', text, re.MULTILINE)
    return headings

if __name__ == "__main__":
    mcp.run()  # 默认 stdio 传输
</code></pre>

<p class="wp-block-paragraph">配置到客户端：</p>

<pre><code class="language-json">{
  "mcpServers": {
    "md-tools": {
      "command": "python",
      "args": ["/绝对路径/server.py"]
    }
  }
}
</code></pre>

<p class="wp-block-paragraph">之后你对 AI 说&#8221;读一下我博客里那篇 MCP 文章的标题结构&#8221;，它就会调用 <code>list_md_headings</code>。</p>

<h2 class="wp-block-heading">六、Step 3：连接远程 API（Resources 示例）</h2>

<p class="wp-block-paragraph">MCP 也能把远程数据当 Resource 暴露，比如把公司 Wiki 的一页变成可引用资源，模型需要时自动拉取，无需把全部内容塞进上下文。</p>

<h2 class="wp-block-heading">七、安全：MCP 最大的坑</h2>

<p class="wp-block-paragraph">MCP 让 AI 能&#8221;动手&#8221;，所以安全是第一位：</p>

<ul class="wp-block-list">
<li><strong>最小授权</strong>：Server 只暴露必要目录/权限；文件系统 Server 只给特定路径。</li>
<li><strong>人工确认</strong>：危险操作（删除、发送、支付）应设确认环节，不让模型静默执行。</li>
<li><strong>可信来源</strong>：只装你信任的 MCP Server，第三方 Server 可能窃取数据或执行恶意指令（&#8221;工具投毒&#8221;攻击）。</li>
<li><strong>隔离运行</strong>：远程 Server 走 HTTPS，校验来源；本地 Server 留意它读写了什么。</li>
<li><strong>审计日志</strong>：记录 AI 调用了哪些工具、传了什么参数，便于追溯。</li>
</ul>

<blockquote class="is-layout-flow wp-block-quote-is-layout-flow">
<p>合规提醒：AI 访问的文件可能含敏感个人信息或商业机密，务必在授权范围内使用，并遵守数据保护相关法规。</p>
</blockquote>

<h2 class="wp-block-heading">八、生态现状（2026）</h2>

<ul class="wp-block-list">
<li><strong>官方 Server 丰富</strong>：filesystem、fetch（网页）、数据库（Postgres/SQLite）、Git、Slack、搜索引擎等。</li>
<li><strong>框架集成</strong>：LangChain、AutoGen、CrewAI 等都能作为 MCP Client 调用 Server。</li>
<li><strong>IDE 原生支持</strong>：Cursor、VS Code 的 AI 插件普遍支持 MCP，<a href="https://waynetalk.com/534/">让编码 Agent 直接操作本地项目</a>。</li>
</ul>

<h2 class="wp-block-heading">九、与 Function Calling 的关系</h2>

<p class="wp-block-paragraph">Function Calling 是&#8221;模型厂商自己的工具调用格式&#8221;；MCP 是&#8221;跨模型、跨客户端的工具连接标准&#8221;。二者互补：MCP 负责&#8221;工具怎么被统一发现与连接&#8221;，底层执行仍可能走各家的 function calling。选 MCP 的理由是<strong>复用与解耦</strong>——一次写好，处处可用。</p>

<h2 class="wp-block-heading">总结</h2>

<p class="wp-block-paragraph">MCP 把&#8221;AI 调用工具&#8221;从 scattered 的定制集成，变成了标准化的&#8221;插拔&#8221;。理解 Host/Server 架构、Tools/Resources/Prompts 三原语，你就能让 AI 安全、可控地操作本地文件、数据库与外部 API。2026 年，会用 MCP 的 Agent 工程师，等于手握一套&#8221;通用遥控器&#8221;——这也是 Agent 真正落地的关键基础设施。</p>

<h2 class="wp-block-heading">FAQ</h2>

<p class="wp-block-paragraph"><strong>Q1：MCP 和直接写代码调 API 有什么不同？</strong><br />
直接写代码是&#8221;一次性集成&#8221;，换模型或换场景要重写；MCP 是&#8221;标准接口&#8221;，Server 写一次，任何支持 MCP 的客户端都能用。它还顺带解决了能力发现（list_tools）与统一鉴权，工程上更省心。</p>

<p class="wp-block-paragraph"><strong>Q2：MCP 安全吗？AI 会不会乱删我文件？</strong><br />
协议本身靠&#8221;最小授权 + 显式路径 + 人工确认&#8221;兜底。风险主要来自不可信的第三方 Server，因此只装可信来源、对写/删操作设确认、保留审计日志，就能把风险压到可控。切记：给 AI 的权限越小越安全。</p>

<p class="wp-block-paragraph"><strong>Q3：普通用户需要自己写 Server 吗？</strong><br />
多数场景不用——直接用社区/官方现成 Server（文件、Git、数据库、搜索等）即可。只有当你有独特内部系统（自研 API、私有数据）且希望 AI 能操作它时，才需要自己写一个轻量 Server，用官方 SDK 几十行代码就能搞定。</p>
