<h2>1. 为什么 Reality 是当前最安全的 TLS 伪装方案？</h2>
<p>在传统的代理伪装方案（如 VMess/VLESS + TLS + Web）中，用户必须：<br />1. 自行购买或注册一个<a href="https://waynetalk.com/221/">境外域名</a>；<br />2. 为该域名配置 DNS 解析并签发 Let&#8217;s Encrypt 证书；<br />3. 在 <a href="https://waynetalk.com/493/">VPS</a> 上部署 Nginx/Caddy 网站进行流量分流。</p>
<p>然而，这种传统模式存在数个<strong>致命的指纹暴露点</strong>：</p>
<ul>
<li><strong>域名信誉度低</strong>：新注册或免费域名极易被防火墙标记并纳入重点监控名单。</li>
<li><strong>主动探测风险</strong>：审查机构扫描服务器 443 端口时，若返回的证书域名和你的真实解析记录一致，但实际上网站内容是一个空模板或静态页，会显著增加被识别为代理服务器的权重。</li>
<li><strong>证书管理维护成本</strong>：证书过期、ACME 续订失败等会导致服务中断。</li>
</ul>
<h3>Reality 核心架构创新</h3>
<p><strong>Reality</strong> 是 Xray-core 团队提出的一套跨时代的 TLS 偷天换日技术：</p>
<ul>
<li><strong>借壳生蛋（SNI 证书借用）</strong>：你的 VPS <strong>完全不需要域名和证书</strong>，而是直接借用正规大型商业网站（如 <code>www.apple.com</code>、<code>gateway.icloud.com</code>、<code>aws.amazon.com</code>、<code>www.microsoft.com</code>）的真实证书。</li>
<li><strong>真·TLS 1.3 握手</strong>：审查系统的 DPI 看到的不仅是合法的真实域名证书，而且所有握手交互、密码套件与公钥交换全部源自真实目标服务器，指纹完全一致。</li>
<li><strong>非对称认证与主动探测粉碎</strong>：</li>
<li>客户端通过 Reality 私钥加密预认证数据发送至服务端。</li>
<li><strong>合法客户端请求</strong>：服务端通过公钥校验成功，直接建立代理隧道传输数据。</li>
<li><strong>审查主动探测或非法爬虫</strong>：服务端无法解密验证，自动将该连接原封不动反向转发给真实的伪装网站。探测者将收到 100% 真实的标准网站响应，根本无法断定这是一台代理服务器。</li>
</ul>

<h2>2. 伪装目标网站（SNI）筛选法则</h2>
<p>选对<a href="https://waynetalk.com/498/">伪装域名</a>（Dest / ServerNames）是保证 Reality 长期稳定运行的关键基石。</p>
<h3>2.1 黄金筛选四要素</h3>
<ol>
<li><strong>支持 TLS 1.3 与 H2</strong>：必须支持现代传输协议。</li>
<li><strong>物理距离与网络延迟接近</strong>：伪装网站的服务器物理 IP 必须与你的 VPS 处于同一国家/地区、甚至同机房，这样 TLS 握手 RTT 才符合物理规律，避免被嗅探到时延反常。</li>
<li><strong>OCSP Stapling 机制正常</strong>：避免证书链验证异常。</li>
<li><strong>不重定向或支持泛域名访问</strong>：避免请求被直接 301/302 跳出。</li>
</ol>
<h3>2.2 伪装域名实测验证命令</h3>
<p>在 VPS 终端执行以下命令，检验候选网站是否支持 TLS 1.3 并能正常握手：</p>
<pre><code class="language-bash"># 测试目标网站的 TLS 版本与握手延迟
curl -Iv https://www.lovelive-anime.jp --tlsv1.3
<h1>或测试境外大厂域名</h1>
curl -Iv https://itunes.apple.com --tlsv1.3
</code></pre>

<h2>3. 服务端部署与密钥生成实战</h2>
<h3>3.1 安装官方最新版 Xray-core</h3>
<p>推荐使用 Xray 官方维护的安装脚本：</p>
<pre><code class="language-bash">bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)"
</code></pre>
<h3>3.2 生成 Reality 必需的密钥对与 Short ID</h3>
<p>Reality 依靠 Curve25519 椭圆曲线非对称密钥进行身份认证：</p>
<pre><code class="language-bash"># 1. 生成公私钥对
xray x25519
<h1>输出示例：</h1>
<h1>Private key: eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHh4= (保留此私钥写入服务端)</h1>
<h1>Public key:  WVlZWVlZWVlZWVlZWVlZWVlZWVlZWVlZWVlZWVlZWVlZ= (保留此公钥写入客户端)</h1>

<h1>2. 生成 16 进制 Short ID（可生成多个，用于客户端校验）</h1>
openssl rand -hex 8
<h1>输出示例：</h1>
<h1>a1b2c3d4e5f60718</h1>
</code></pre>
<h3>3.3 编写标准服务端配置文件 (<code>/usr/local/etc/xray/config.json</code>)</h3>
<pre><code class="language-json">{
  "log": {
    "loglevel": "warning"
  },
  "inbounds": [
    {
      "port": 443,
      "protocol": "vless",
      "settings": {
        "clients": [
          {
            "id": "27d6d338-7bb8-4f51-bdfc-8a242f36d123", // 生成命令：xray uuid
            "flow": "xtls-rprx-vision"                     // 开启 XTLS Vision 流控
          }
        ],
        "decryption": "none"
      },
      "streamSettings": {
        "network": "tcp",
        "security": "reality",
        "realitySettings": {
          "show": false,
          "dest": "www.lovelive-anime.jp:443", // 真实借用的伪装网站
          "xver": 0,
          "serverNames": [
            "www.lovelive-anime.jp",
            "lovelive-anime.jp"
          ],
          "privateKey": "eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHh4eHh4=", // 刚生成的 Private key
          "shortIds": [
            "a1b2c3d4e5f60718" // 刚生成的 Short ID
          ]
        }
      },
      "sniffing": {
        "enabled": true,
        "destOverride": ["http", "tls", "quic"]
      }
    }
  ],
  "outbounds": [
    {
      "protocol": "freedom"
    }
  ]
}
</code></pre>
<p>启动并验证服务运行状态：</p>
<pre><code class="language-bash"># 启动并设置开机启动
systemctl enable --now xray

<h1>查看服务日志与运行状态</h1>
systemctl status xray
</code></pre>

<h2>5. 常见实操故障排查与调优（FAQ）</h2>
<h3>Q1: 为什么客户端报错 <code>handshake failure</code> 或 <code>connection reset</code>？</h3>
<ul>
<li><strong>排查步骤</strong>：</li>
</ul>
<ol>
<li>检查客户端指纹（Fingerprint）是否填写了 <code>chrome</code> 或 <code>safari</code>；</li>
<li>测试伪装网站 <code>dest</code> 是否在本地能够直接 ping 通，有的国外冷门网站可能在某些运营商直接被封禁；</li>
<li>检查客户端填写的 <strong>PublicKey</strong> 是否误填成了 PrivateKey。</li>
</ol>
<h3>Q2: 为什么开启了 <code>xtls-rprx-vision</code> 速度反而变慢了？</h3>
<ul>
<li><strong>解答</strong>：<code>xtls-rprx-vision</code> 的核心目标是在检测到内层 TLS 流量时直接跳过加密封装（splice 直接穿透内核），但在部分劣质的虚拟化架构或开启了高强度代理分流软件时可能出现上下文切换。通常在主流 KVM VPS 上，Vision 能显著降低 CPU 占用并提升吞吐量。</li>
</ul>
<h3>Q3: Reality 可以搭配 CDN（如 Cloudflare）使用吗？</h3>
<ul>
<li><strong>解答</strong>：<strong>绝对不行</strong>。Reality 的核心原理是借用目标网站的 TLS 握手，而 CDN 的工作原理是反向代理并要求自持证书。如果接入 CDN，CDN 无法解密 Reality 的私有协商流量，连接会立即中断。Reality 仅适用于<a href="https://waynetalk.com/shadowrocket-ios-tutorial/">客户端</a>直接直连 VPS。</li>
</ul>
