<p><a href="https://waynetalk.com/vless-setup-openwrt-guide/">自建节点最大的痛点往往不是协议本身</a>，而是<strong>部署环境混乱与维护成本高昂</strong>：直接在宿主机裸机跑一键脚本，容易污染系统依赖、植入不明后门，一旦环境崩盘只能重装系统。</p>
<p>使用 <strong>Docker + Docker Compose</strong> 进行容器化部署，具有极高的隔离性与可移植性：配置文件完全透明，升级只需一条命令，迁移服务器直接打包目录即可完成。</p>
<p>本文将以通用的 <strong>Debian 12 纯净系统</strong>为例，带你零基础跑通基于 Docker 的 <strong>Sing-box（主打轻量全能）与 Xray（生态成熟）</strong> 核心服务端，并以目前<a href="https://waynetalk.com/490/">抗封锁能力最强的 <strong>VLESS-Reality</strong></a> 协议落地。</p>
<hr />
<h2>一、 服务器环境准备与基础安全加固</h2>
<p>在开工部署之前，必须先将 <a href="https://waynetalk.com/542/">VPS</a> 的系统环境与网络内核优化到位。</p>
<h3>1. 更新系统并启用 BBR 拥塞控制</h3>
<p>登录 <a href="https://waynetalk.com/free-vps-2026/">VPS</a> 终端后，首先更新系统依赖并开启 Linux 内核原生的 BBR 加速：</p>
<pre><code class="language-bash line-numbers"># 更新系统软件包
apt update && apt upgrade -y

# 安装常用基础工具
apt install -y curl wget git socat vim ufw

# 检查并开启 BBR（Debian 12 默认内核已支持）
echo "net.core.default_qdisc=fq" >> /etc/sysctl.conf
echo "net.ipv4.tcp_congestion_control=bbr" >> /etc/sysctl.conf
sysctl -p

</code></pre>
<p>运行 <code>sysctl net.ipv4.tcp_congestion_control</code>，输出为 <code>bbr</code> 即表示开启成功。</p>
<h3>2. 基础安全设置（防火墙配置）</h3>
<p>Reality 默认建议伪装在标准 HTTPS 端口 <code>443</code>。确保防火墙放行 SSH 端口与 443 端口：</p>
<pre><code class="language-bash line-numbers">ufw default deny incoming
ufw default allow outgoing
ufw allow ssh
ufw allow 443/tcp
ufw --force enable

</code></pre>
<hr />
<h2>二、 安装 Docker 与 Docker Compose</h2>
<p>使用 Docker 官方推荐的一键脚本快速部署最新版引擎：</p>
<pre><code class="language-bash line-numbers"># 下载并执行 Docker 官方安装脚本
curl -fsSL https://get.docker.com | bash

# 验证 Docker 与 Compose 插件版本
docker --version
docker compose version

</code></pre>
<hr />
<h2>三、 核心服务端部署实战（以 Sing-box 为例）</h2>
<p>Sing-box 内存占用极低且对新协议支持迅捷，这里以此作为主选方案。</p>
<h3>1. 创建项目目录结构</h3>
<p>规范化管理文件，避免零散文件混杂：</p>
<pre><code class="language-bash line-numbers">mkdir -p /opt/sing-box
cd /opt/sing-box

</code></pre>
<h3>2. 生成 Reality 专属密钥对与 UUID</h3>
<p>Reality 协议需要一对独有的私钥（Private Key）和公钥（Public Key），以及一个通信认证的 ShortId 和 UUID：</p>
<pre><code class="language-bash line-numbers"># 临时运行 Sing-box 容器生成密钥对
docker run --rm ghcr.io/sagernet/sing-box:latest generate reality-keypair

</code></pre>
<p>终端会输出如下格式的密钥信息，<strong>务必记录下来</strong>：</p>
<pre><code class="language-text line-numbers">PrivateKey:  <你的私钥>
PublicKey:   <你的公钥> (客户端填这个)

</code></pre>
<p>接着生成 UUID 和 ShortId：</p>
<pre><code class="language-bash line-numbers"># 生成随机 UUID
cat /proc/sys/kernel/random/uuid

# 生成 8 位 16 进制 ShortId
openssl rand -hex 8

</code></pre>
<h3>3. 编写 <code>config.json</code> 配置文件</h3>
<p>在 <code>/opt/sing-box</code> 目录下创建配置文件：</p>
<pre><code class="language-bash line-numbers">vim config.json

</code></pre>
<p>将以下配置模版粘贴进去，并替换其中的四个占位符：<code>&lt;你的UUID&gt;</code>、<code>&lt;你的私钥&gt;</code>、<code>&lt;你的ShortId&gt;</code> 以及伪装目标域名：</p>
<pre><code class="language-json line-numbers">{
  "log": {
    "level": "info",
    "timestamp": true
  },
  "inbounds": [
    {
      "type": "vless",
      "tag": "vless-in",
      "listen": "::",
      "listen_port": 443,
      "users": [
        {
          "uuid": "<你的UUID>",
          "flow": "xtls-rprx-vision"
        }
      ],
      "tls": {
        "enabled": true,
        "server_name": "gateway.icloud.com",
        "reality": {
          "enabled": true,
          "handshake": {
            "server": "gateway.icloud.com",
            "server_port": 443
          },
          "private_key": "<你的私钥>",
          "short_id": [
            "<你的ShortId>"
          ]
        }
      }
    }
  ],
  "outbounds": [
    {
      "type": "direct",
      "tag": "direct"
    },
    {
      "type": "block",
      "tag": "block"
    }
  ]
}

</code></pre>
<blockquote><p>
  <strong>注</strong>：此处 <code>server_name</code> 与 <code>server</code> 均选用了支持 TLS 1.3 且物理直连延迟较低的大厂域名（如 <code>gateway.icloud.com</code> 或 <code>[www.apple.com](https://www.apple.com)</code>）。关于如何挑选最抗封的伪装域名，将在第 3 篇专门拆解。
</p></blockquote>
<h3>4. 编写 <code>docker-compose.yml</code> 容器编排文件</h3>
<p>同目录下创建容器配置文件：</p>
<pre><code class="language-bash line-numbers">vim docker-compose.yml

</code></pre>
<p>内容如下：</p>
<pre><code class="language-yaml line-numbers">services:
  sing-box:
    image: ghcr.io/sagernet/sing-box:latest
    container_name: sing-box
    restart: always
    network_mode: host
    volumes:
      - ./config.json:/etc/sing-box/config.json
    command: run -c /etc/sing-box/config.json

</code></pre>
<blockquote><p>
  <strong>说明</strong>：这里采用 <code>network_mode: host</code> 可以降低 Docker 容器内部端口转发的 NAT 开销，让网络吞吐性能拉满。
</p></blockquote>
<hr />
<h2>四、 启动与状态检查</h2>
<p>在 <code>/opt/sing-box</code> 目录下执行启动命令：</p>
<pre><code class="language-bash line-numbers"># 后台拉取镜像并启动
docker compose up -d

# 查看容器运行日志，确认是否有配置报错
docker compose logs -f

</code></pre>
<p>如果看到类似 <code>sing-box started</code> 且没有 error 报错，说明服务端已经在 443 端口平稳监听。</p>
<hr />
<h2>五、 生成客户端通用导入链接</h2>
<p>将以下信息按照标准 VLESS URI 规范拼接，即可直接复制导入到 Clash Verge Rev、v2rayN、Shadowrocket 等常见客户端：</p>
<pre><code class="language-text line-numbers">vless://<你的UUID>@<你的VPS_IP>:443?encryption=none&flow=xtls-rprx-vision&security=reality&sni=gateway.icloud.com&fp=chrome&pbk=<你的公钥>&sid=<你的ShortId>&type=tcp#My-Reality-Node

</code></pre>
<h3>关键参数检查表：</h3>
<ul>
<li><strong>IP</strong>：你的 VPS 公网 IPv4 / IPv6 地址</li>
<li><strong>Port</strong>：<code>443</code></li>
<li><strong>UUID</strong>：第三节中生成的 UUID</li>
<li><strong>Flow</strong>：<code>xtls-rprx-vision</code></li>
<li><strong>Security</strong>：<code>reality</code></li>
<li><strong>SNI</strong>：<code>gateway.icloud.com</code>（与服务端配置保持完全一致）</li>
<li><strong>Fingerprint (fp)</strong>：<code>chrome</code>（必须模拟真实浏览器指纹）</li>
<li><strong>Public Key (pbk)</strong>：第三节步骤 2 中生成的 <strong>公钥</strong>（切勿填成私钥）</li>
<li><strong>ShortId (sid)</strong>：生成的 8 位 ShortId</li>
</ul>
