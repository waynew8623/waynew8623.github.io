<h2 class="wp-block-heading">整体架构</h2>

<pre><code>Uptime Kuma ──(Webhook 通知)──▶ n8n Webhook 节点
                                      │
                                      ├─▶ Telegram 节点
                                      ├─▶ 企业微信 机器人节点
                                      └─▶ (可选) 数据库记录/看板
</code></pre>

<p class="wp-block-paragraph">当监控项状态变化时，Kuma 向 n8n 暴露的 Webhook URL 发送 JSON，n8n 解析后分发。</p>

<h2 class="wp-block-heading">第一步：Uptime Kuma 通知配置</h2>

<p class="wp-block-paragraph">在 Uptime Kuma 中「通知」→「创建通知」，类型选择 <strong>Webhook</strong>，填入 n8n 的 Webhook 地址（需<a href="https://waynetalk.com/547/">公网可访问</a>，参考前文反向代理部署）：</p>

<pre><code>https://n8n.example.com/webhook/kuma-alert
</code></pre>

<p class="wp-block-paragraph">请求体（Kuma 默认会 POST 一份 JSON，包含 <code>monitor.name</code>、<code>status</code>、<code>msg</code>、<code>心跳</code>等信息）。你也可以自定义 Payload：</p>

<pre><code class="language-json">{
  "monitor": "{{ monitor.name }}",
  "url": "{{ monitor.url }}",
  "status": "{{ status }}",
  "msg": "{{ msg }}",
  "time": "{{ time }}",
  "type": "{{ type }}"
}
</code></pre>

<blockquote class="is-layout-flow wp-block-quote-is-layout-flow">
<p>注意：<code>status</code> 取值通常为 <code>up</code> / <code>down</code> / <code>cert</code> 等；<code>msg</code> 会携带「Certificate #1 will expire in &#8230;」这类描述。</p>
</blockquote>

<h2 class="wp-block-heading">第二步：n8n Webhook 接收节点</h2>

<p class="wp-block-paragraph">在 n8n 中新建工作流，第一个节点选 <strong>Webhook</strong>，配置：</p>

<ul class="wp-block-list">
<li>HTTP Method：<code>POST</code></li>
<li>Path：<code>kuma-alert</code></li>
<li>Response Mode：<code>On Received</code>（立即响应，避免 Kuma 超时重试）</li>
<li>Authentication：建议开启 <strong>Header Auth</strong> 或 <strong>Basic Auth</strong>，防止裸调。</li>
</ul>

<p class="wp-block-paragraph">Webhook 收到的数据结构示例：</p>

<pre><code class="language-json">{
  "monitor": "官网首页",
  "url": "https://www.example.com",
  "status": "down",
  "msg": "Host unreachable",
  "time": "2026-09-05 02:13:00"
}
</code></pre>

<h2 class="wp-block-heading">第三步：用 Switch 节点做告警分级</h2>

<p class="wp-block-paragraph">添加一个 <strong>Switch</strong> 节点，按 <code>status</code> 分流：</p>

<ul class="wp-block-list">
<li>当 <code>status == "down"</code> → 高优先级分支（推 Telegram + 企微，并 @ 负责人）</li>
<li>当 <code>status == "up"</code> 且之前为 down → 恢复通知分支</li>
<li>当 <code>msg</code> 包含 <code>Certificate</code> 或 <code>expire</code> → 证书告警分支</li>
<li>其他 → 普通日志分支</li>
</ul>

<p class="wp-block-paragraph">Switch 配置（按字段 <code>status</code>）：</p>

<pre><code>Routing Rules:
  contains "down"       → 输出 0（严重）
  contains "up"         → 输出 1（恢复）
  contains "Certificate"→ 输出 2（证书）
  否则                   → 输出 3（其他）
</code></pre>

<h2 class="wp-block-heading">第四步：推送到 Telegram</h2>

<p class="wp-block-paragraph">添加 <strong><a href="https://waynetalk.com/528/">Telegram</a></strong> 节点（需先在 @BotFather 创建 Bot 拿到 Token，并在群组内 <code>/getid</code> 拿到 Chat ID）：</p>

<ul class="wp-block-list">
<li>Resource：Send Message</li>
<li>Chat ID：<code>-1001234567890</code></li>
<li>Text（用表达式拼装）：</li>
</ul>

<pre><code>🚨【n8n 监控告警】
监控项：{{ <span class="katex math inline">json.monitor }}
地址：{{</span>json.url }}
状态：{{ <span class="katex math inline">json.status }}
详情：{{</span>json.msg }}
时间：{{ $json.time }}
</code></pre>

<p class="wp-block-paragraph">严重分支可额外 @ 负责人：<code>@oncall_zhang</code>，并加 <code>parse_mode=Markdown</code>。</p>

<h2 class="wp-block-heading">第五步：推送到企业微信</h2>

<p class="wp-block-paragraph">企业微信群机器人最方便。在企微群「添加群机器人」拿到 Webhook Key，用 <strong>HTTP Request</strong> 节点 <code>POST</code>：</p>

<pre><code>URL: https://qyapi.weixin.qq.com/cgi-bin/webhook/send?key=YOUR_KEY
Method: POST
Body (JSON):
{
  "msgtype": "markdown",
  "markdown": {
    "content": "**🚨 n8n 监控告警**\n> 监控项：{{ <span class="katex math inline">json.monitor }}\n> 地址：{{</span>json.url }}\n> 状态：{{ <span class="katex math inline">json.status }}\n> 详情：{{</span>json.msg }}\n> 时间：{{ $json.time }}"
  }
}
</code></pre>

<blockquote class="is-layout-flow wp-block-quote-is-layout-flow">
<p>群机器人 Markdown 仅支持部分语法（不支持图片、仅部分排版），注意转义 <code>@</code> 等字符。</p>
</blockquote>

<h2 class="wp-block-heading">第六步：告警收敛（去重 + 静默窗口）</h2>

<p class="wp-block-paragraph">高频抖动会产生告警风暴。加一个 <strong>Code</strong> 节点做时间窗口去重：</p>

<pre><code class="language-javascript">// 简单去重：同一 monitor 5 分钟内只告警一次
const now = Date.now();
const mem = <span class="katex math inline">items().length ?</span>json : null;
// 实际生产中建议用 Redis 或 DB 记录上次告警时间
// 此处示意逻辑
return $input.all();
</code></pre>

<p class="wp-block-paragraph">更稳妥的做法是用 n8n 的 <strong>Redis</strong> 节点或外部数据库记录 <code>monitor + lastAlertTs</code>，超过阈值才放行。</p>

<h2 class="wp-block-heading">第七步：恢复通知与值班升级</h2>

<p class="wp-block-paragraph">当 <code>status == "up"</code> 时发送「服务已恢复」消息，并可在 30 分钟内连续 3 次 down 未恢复时，通过 Telegram 私信值班同学升级处理。</p>

<h2 class="wp-block-heading">工作流 JSON 关键结构说明</h2>

<p class="wp-block-paragraph">完整 workflow 包含节点：<code>Webhook → Switch → Telegram(严重) / Telegram(恢复) / HTTP(企微) / Code(记录)</code>。导出 JSON 后可在团队内复用，核心是 Webhook 的 <code>path</code> 与 Switch 的路由规则保持一致。</p>

<p class="wp-block-paragraph">Uptime Kuma 负责「看见问题」，n8n 负责「把问题送到该看的人面前」。这套组合零代码成本、完全自托管，是 2026 年中小团队最性价比的监控告警方案。</p>

<h2 class="wp-block-heading">FAQ</h2>

<p class="wp-block-paragraph"><strong>Q1：n8n Webhook 必须公网可访问吗？</strong><br />
是的，因为 Uptime Kuma 主动 POST 给你。若 n8n 在内网，可用 Cloudflare Tunnel 或 frp 把 <code>https://n8n.example.com/webhook/...</code> 暴露出去，并务必开启鉴权。</p>

<p class="wp-block-paragraph"><strong>Q2：企业微信机器人有频率限制吗？</strong><br />
单机器人每分钟约 20 条消息上限，超出会限流。高并发场景建议做聚合或升级为应用消息。</p>

<p class="wp-block-paragraph"><strong>Q3：如何避免证书过期告警刷屏？</strong><br />
证书告警只在「剩余天数 < 阈值」时由 Kuma 触发一次，n8n 侧再用去重窗口压制即可。</p>
