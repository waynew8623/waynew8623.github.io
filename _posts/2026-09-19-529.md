<h2 class="wp-block-heading">架构</h2>

<pre><code>邮件触发（IMAP/Webhook）
   │
   ├─ 过滤「来自某发件人 + 主题含某关键词」的附件
   ├─ 下载附件（二进制）
   ├─ 本地加密（GPG / AES）
   ├─ 上传到 WebDAV 或 S3
   └─ 写索引到数据库 + 通知
</code></pre>

<h2 class="wp-block-heading">第一步：监听邮件附件</h2>

<p class="wp-block-paragraph">用 <strong>IMAP</strong> 节点读取未读邮件：</p>

<ul class="wp-block-list">
<li>筛选发件人：<code>FROM</code> 包含 <code>finance@partner.com</code></li>
<li>筛选主题：<code>SUBJECT</code> 包含「合同」「报表」</li>
<li>开启「Download Attachments」</li>
</ul>

<pre><code>搜索条件示例（IMAP）：
  FROM "finance@partner.com" SUBJECT "合同" UNSEEN
</code></pre>

<p class="wp-block-paragraph">用 <strong>Filter</strong> 节点只保留需要的附件类型（如 <code>.pdf</code>、<code>.xlsx</code>）：</p>

<pre><code>条件：attachment.fileName 匹配 /\.(pdf|xlsx|docx)$/i
</code></pre>

<h2 class="wp-block-heading">第二步：本地加密附件</h2>

<p class="wp-block-paragraph">在 n8n 执行节点用 <strong>Execute Command</strong>（或 Code 调子进程）<a href="https://waynetalk.com/902/">运行 GPG</a> 对称加密：</p>

<pre><code class="language-bash"># 用口令加密（密钥来自环境变量 <span class="katex math inline">ENC_PASS）
gpg --batch --yes --passphrase "</span>ENC_PASS" \
    --cipher-algo AES256 \
    --symmetric --output "<span class="katex math inline">{file}.gpg" "</span>{file}"
</code></pre>

<p class="wp-block-paragraph">在 n8n <strong>Execute Command</strong> 节点：</p>

<ul class="wp-block-list">
<li>Command：<code>gpg</code></li>
<li>Args：<code>--batch --yes --passphrase=<span class="katex math inline">ENV_ENC_PASS --cipher-algo AES256 --symmetric --output /tmp/{{</span>json.fileName }}.gpg /tmp/{{ $json.fileName }}</code></li>
</ul>

<blockquote class="is-layout-flow wp-block-quote-is-layout-flow">
<p>更安全的做法是使用非对称加密（对方公钥），这样连口令都不落盘。生产推荐 <code>gpg --encrypt --recipient recipient@key.id</code>。</p>
</blockquote>

<p class="wp-block-paragraph">加密后把 <code>.gpg</code> 文件作为新二进制读回 n8n（<strong>Read Binary File</strong> 节点）。</p>

<h2 class="wp-block-heading">第三步：上传到 WebDAV 自建网盘</h2>

<p class="wp-block-paragraph">用 <strong>HTTP Request</strong> 节点对 WebDAV 发 <code>PUT</code>：</p>

<pre><code>Method: PUT
URL: https://dav.your-nas.com/remote.php/dav/files/admin/inbox/{{ <span class="katex math inline">json.fileName }}.gpg
Headers:
  Authorization: Basic {{</span>base64(USER:PASS) }}
  Content-Type: application/octet-stream
Body: (binary) 选择加密后的 .gpg 二进制
</code></pre>

<p class="wp-block-paragraph">常见自建网盘：<a href="https://waynetalk.com/519/">Nextcloud、群晖</a> Drive、FileBrowser，均提供 WebDAV 端点，配置一致。</p>

<h2 class="wp-block-heading">第四步：上传到 S3 对象存储</h2>

<p class="wp-block-paragraph"><a href="https://waynetalk.com/546/">用 n8n 官方的 <strong>S3</strong> 节点</a>（或 <strong>AWS S3</strong> 节点）：</p>

<ul class="wp-block-list">
<li>Operation：<code>Upload</code></li>
<li>Bucket：<code>company-archive</code></li>
<li>Key：<code>inbox/{{ <span class="katex math inline">now.format('yyyy/MM/dd') }}/{{</span>json.fileName }}.gpg</code></li>
<li>Region / Access Key / Secret：来自凭据</li>
<li>二进制属性：<code>data</code>（加密文件）</li>
</ul>

<p class="wp-block-paragraph">S3 还可顺手开启服务端加密（SSE-KMS）做「双重保险」。</p>

<h2 class="wp-block-heading">第六步：清理与错误处理</h2>

<ul class="wp-block-list">
<li>上传成功后标记邮件已读（<code>IMAP</code> 节点 <code>Post Process: "Mark as Read"</code>），避免重复处理。</li>
<li>加密/上传失败 → 进错误分支，保留原始附件到临时区并告警，人工介入。</li>
<li>定期清理 <code>/tmp</code> 明文临时文件，防止密钥文件残留（用 Execute Command 在末尾 <code>rm</code>）。</li>
</ul>

<h2 class="wp-block-heading">多端同步效果</h2>

<ul class="wp-block-list">
<li>手机/电脑装 WebDAV 客户端即可直接浏览加密归档（需解密查看）。</li>
<li>S3 可作异地备份，配合生命周期规则转冷存储降本。</li>
<li>全链路无第三方云盘，数据主权完整。</li>
</ul>

<h2 class="wp-block-heading">安全清单</h2>

<ul class="wp-block-list">
<li>加密口令/私钥存 n8n 凭据，勿写进工作流。</li>
<li><code>/tmp</code> 明文文件处理完即删。</li>
<li>WebDAV/S3 用最小权限账号。</li>
<li>启用访问日志，便于审计「谁的文件、何时归档」。</li>
</ul>

<h2 class="wp-block-heading">总结</h2>

<p class="wp-block-paragraph">把邮件附件变成「自动加密归档」的资产，既统一了散落的合同报表，又把泄露风险压到最低。n8n 在这一链路里扮演「安全搬运工」，WebDAV/S3 任你选。</p>

<h2 class="wp-block-heading">FAQ</h2>

<p class="wp-block-paragraph"><strong>Q1：GPG 对称加密和非对称加密怎么选？</strong><br />
对称（口令）简单、单人可用；非对称（公钥）更适合「多人发、仅指定人能解」的场景，且口令不落盘更安全。团队建议非对称。</p>

<p class="wp-block-paragraph"><strong>Q2：WebDAV 上传大文件会超时吗？</strong><br />
大文件建议分块或调高 n8n HTTP 节点的超时，并确认网盘端单文件上限。S3 对大文件更友好（支持分片上传）。</p>

<p class="wp-block-paragraph"><strong>Q3：明文临时文件会不会泄露？</strong><br />
只要工作流结尾用 Execute Command <code>rm -f</code> 清理，且 <code>/tmp</code> 不在公网可访问路径，风险极低。更稳的是全程用内存二进制、不落盘。</p>
