<h2 class="wp-block-heading">引言：多数&#8221;模型不行&#8221;，其实是&#8221;提示词不行&#8221;</h2>

<p class="wp-block-paragraph">同样的模型，有人用它产出可直接上线的代码，有人得到一堆废话。差距不在模型，而在<strong>你把任务描述得够不够清楚、把输出格式约束得够不够死</strong>。</p>

<p class="wp-block-paragraph">2026 年，Prompt 工程的核心已经从&#8221;堆形容词&#8221;进化到&#8221;结构化沟通&#8221;：用框架组织信息，用 JSON 锁定输出，<a href="https://waynetalk.com/539/">用工具调用（function calling）让模型对接真实系统</a>。本文给你一套可复用的写法。</p>

<h2 class="wp-block-heading">一、为什么&#8221;结构化&#8221;比&#8221;华丽&#8221;重要？</h2>

<p class="wp-block-paragraph">自然语言模糊，机器需要边界。一个模糊提示词：</p>

<pre><code class="language-text">帮我分析下这批用户评论，说说好不好。
</code></pre>

<p class="wp-block-paragraph">模型不知道：分析什么维度、输出什么格式、要不要打分。结果千人千面，无法程序化处理。</p>

<p class="wp-block-paragraph">结构化之后：</p>

<pre><code class="language-text">你是一个用户研究分析师。请基于以下评论，按"情感/主题/痛点"三维度分析，
输出 JSON：{ "sentiment": "正面|中性|负面", "themes": [...], "pains": [...] }。
仅依据给定文本，不得编造。
</code></pre>

<p class="wp-block-paragraph">差别立现：输出可被代码直接消费。</p>

<h3 class="wp-block-heading">模板</h3>

<pre><code class="language-text"># Role
你是一名资深 [职业]，擅长 [领域]。

# Task
[用一句话描述目标]。

# Context
- 背景：[...]
- 输入：[...]
- 约束：[...]

# Detail
执行步骤：
1. [...]
2. [...]
参考示例（few-shot）：
输入：... → 输出：...

# Format
严格按以下结构输出：
{
  "字段1": "类型/说明",
  "字段2": [...]
}
不要输出格式之外的内容。
</code></pre>

<h2 class="wp-block-heading">三、Few-shot：给例子比讲道理管用</h2>

<p class="wp-block-paragraph">对格式敏感的任务，塞 1–3 个示例，模型立刻&#8221;懂规矩&#8221;：</p>

<pre><code class="language-text">把用户问题分类为 billing / tech / other。
示例：
Q: 我账单多扣了钱 → {"category":"billing"}
Q: App 闪退 → {"category":"tech"}
Q: 你们周末上班吗 → {"category":"other"}
现在分类：Q: 怎么开发票
</code></pre>

<h2 class="wp-block-heading">四、结构化输出（JSON）控制</h2>

<p class="wp-block-paragraph">让模型稳定吐 JSON，是接入系统的关键。三种办法：</p>

<h3 class="wp-block-heading">方法 1：提示词硬约束（最通用）</h3>

<p class="wp-block-paragraph">如上 RTCDF 的 Format 块，明确要求&#8221;只输出 JSON，不含解释&#8221;。但纯提示词偶有&#8221;包裹在 <code>json</code> 里&#8221;或加前缀的情况，解析前需清洗。</p>

<h3 class="wp-block-heading">方法 2：API 的 JSON Mode / Structured Output</h3>

<p class="wp-block-paragraph"><a href="https://waynetalk.com/532/">主流模型（GPT-5 系列、Claude 4.x/5、Gemini 3）</a>支持原生结构化输出。以 OpenAI 兼容接口为例：</p>

<pre><code class="language-python">from openai import OpenAI
client = OpenAI()

resp = client.chat.completions.create(
    model="gpt-5",
    response_format={
        "type": "json_schema",
        "json_schema": {
            "name": "review_analysis",
            "schema": {
                "type": "object",
                "properties": {
                    "sentiment": {"type": "string", "enum": ["正面","中性","负面"]},
                    "themes": {"type": "array", "items": {"type": "string"}},
                    "pains": {"type": "array", "items": {"type": "string"}}
                },
                "required": ["sentiment","themes","pains"]
            }
        }
    },
    messages=[{"role":"user","content":"分析这条评论：快递太慢了，但东西不错。"}]
)
print(resp.choices[0].message.content)
</code></pre>

<p class="wp-block-paragraph">这样模型输出<strong>强制符合 schema</strong>，解析零意外。Claude 用 <code>JSON mode</code>、Gemini 用 <code>response_schema</code>，思路一致。</p>

<h3 class="wp-block-heading">方法 3：函数调用（Function Calling）</h3>

<p class="wp-block-paragraph">比 JSON 更进一层——让模型&#8221;决定调用哪个函数、填什么参数&#8221;，由你的代码真正执行：</p>

<pre><code class="language-python">tools = [{
    "type": "function",
    "function": {
        "name": "create_ticket",
        "description": "为用户创建售后工单",
        "parameters": {
            "type": "object",
            "properties": {
                "order_id": {"type": "string"},
                "issue": {"type": "string"}
            },
            "required": ["order_id","issue"]
        }
    }
}]

resp = client.chat.completions.create(
    model="gpt-5",
    tools=tools,
    messages=[{"role":"user","content":"订单 A123 收到的商品破损，帮我建个工单。"}]
)
# 模型返回 tool_calls，你的代码调用 create_ticket("A123","商品破损")
</code></pre>

<blockquote class="is-layout-flow wp-block-quote-is-layout-flow">
<p>2026 进展：GPT-5 还引入了&#8221;自定义工具&#8221;——模型可用纯文本而非 JSON 调用工具，进一步降低出错率。但工程上仍推荐 schema 化以保证可解析。</p>
</blockquote>

<h2 class="wp-block-heading">六、调试技巧</h2>

<ul class="wp-block-list">
<li><strong>最小可复现</strong>：先 1 条样本调通格式，再放量。</li>
<li><strong>固定种子/温度</strong>：需要稳定输出时设 <code>temperature=0</code>。</li>
<li><strong>分层校验</strong>：先校验 JSON 合法性，再校验业务字段。</li>
<li><strong>让模型自检</strong>：&#8221;先输出思考，再输出最终 JSON&#8221;，用思考辅助、最终只取 JSON。</li>
</ul>

<h2 class="wp-block-heading">七、把 Prompt 当&#8221;代码&#8221;管理</h2>

<ul class="wp-block-list">
<li>存为模板文件，用变量填充（如 <code>{{user_input}}</code>）。</li>
<li>版本化：改一处就记录，配回归测试集。</li>
<li>集中存放：团队共享<a href="https://waynetalk.com/446/">高质量 Prompt 库</a>，避免每个人各写一套。</li>
</ul>

<h2 class="wp-block-heading">总结</h2>

<p class="wp-block-paragraph">2026 年的 Prompt 工程，本质是&#8221;给 AI 写清晰的接口文档&#8221;：用 RTCDF 框架组织信息，用 few-shot 示范格式，用 JSON Schema / function calling 锁定输出。当你能把模型输出直接喂进代码，AI 才真正从&#8221;聊天玩具&#8221;变成&#8221;系统组件&#8221;。</p>

<h2 class="wp-block-heading">FAQ</h2>

<p class="wp-block-paragraph"><strong>Q1：JSON Mode 和 Function Calling 该用哪个？</strong><br />
只想要结构化文本（如分类、抽取），用 JSON Mode / Structured Output 最简单；需要模型&#8221;触发真实动作&#8221;（查库、发消息、调 API），用 Function Calling。两者可叠加：函数参数也用 JSON Schema 约束。</p>

<p class="wp-block-paragraph"><strong>Q2：模型偶尔还是输出多余解释怎么办？</strong><br />
三层兜底：① 提示词写明&#8221;只输出 JSON&#8221;；② 优先用 API 原生 structured output（强约束）；③ 解析前用代码剥离 <code>json</code> 包裹与前缀。生产环境务必做解析失败的兜底分支。</p>

<p class="wp-block-paragraph"><strong>Q3：提示词越长越好吗？</strong><br />
不是。过长会稀释重点、增加成本与噪声。原则是&#8221;必要信息齐全、冗余一律删&#8221;。角色一句、任务一句、关键约束与 1–2 示例，往往胜过洋洋洒洒三屏。</p>
