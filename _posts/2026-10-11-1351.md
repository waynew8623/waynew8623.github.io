<p>核心摘要（Key Takeaways）：<br />
&#8211; frp 是&#8221;反向代理式&#8221;内网穿透：内网机器主动向外连接有公网 IP 的 frps，<strong>家里没有公网 IP 照样能用</strong>。<br />
&#8211; 最小可用配置只需十几行 TOML：frps 定好 token 与端口，frpc 声明要暴露哪些内网服务。<br />
&#8211; 免费 SSL 证书用 acme.sh + Let&#8217;s Encrypt + DNS-01 验证申请通配符证书，一张证书覆盖所有子域名。<br />
&#8211; 家庭宽带 IP 会变：给 frps 绑定域名并配合 DDNS 自动更新解析，frpc 永远找得到服务器。</p>
<p>家里的树莓派跑着 Home Assistant，NAS 里存着全家照片，还搭了个个人博客——在家里局域网一切正常，可一出门就全都连不上。找运营商要公网 IP？答复大多是&#8221;没有&#8221;。路由器上做端口映射？没有公网 IP，映射了也没用。</p>

<h2>一、frp 是怎么工作的（先建立心智模型）</h2>
<p>frp 由两部分组成：<strong>frps（服务端）</strong> 跑在有公网 IP 的 VPS 上，<strong>frpc（客户端）</strong> 跑在内网机器（树莓派、NAS、家用电脑）上。</p>
<pre><code class="line-numbers">你的手机/电脑              公网 VPS (frps)                 家里内网 (frpc)
    │                          │                                 │
    │── https://nas.你的域名 ──▶│  vhostHTTPSPort                 │
    │                          │── 隧道（frpc 主动向外建连） ──▶ │──▶ 树莓派 :5000
</code></pre>
<p>关键洞察：<strong>连接方向是&#8221;由内向外&#8221;</strong>。frpc 主动向 frps 发起长连接并维持心跳，NAT 网关和防火墙对&#8221;出去&#8221;的连接一般不拦截——这就是没有公网 IP 也能穿透的根本原因。frps 收到公网请求后，通过这条隧道把流量转发回内网。</p>
<p>注意 frp 需要一台有公网 IP 的服务器做中转。如果你连 VPS 都不想买，可以看本站另一篇：<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/547/">无公网 IP 方案：Cloudflare Tunnel、Tailscale 与 ZeroTier 实现远程访问</a>。</p>

<h2>三、frp 服务端配置（frps，跑在 VPS 上）</h2>
<h3>1. 下载安装</h3>
<p>到 GitHub Releases 下载最新版（<strong>以官方页面为准</strong>；v0.52 起配置文件改为 TOML 格式，旧 INI 已废弃）：</p>
<pre><code class="language-bash line-numbers"># 先查最新版本号（以官方返回为准）
curl -sL https://api.github.com/repos/fatedier/frp/releases/latest | grep '"tag_name"'

# 再下载对应版本（下面以 v0.xx.x 占位，请替换为上一步查到的版本）
wget https://github.com/fatedier/frp/releases/download/v0.xx.x/frp_0.xx.x_linux_amd64.tar.gz
tar xzf frp_0.xx.x_linux_amd64.tar.gz
cd frp_0.xx.x_linux_amd64
</code></pre>
<h3>2. 编写 frps.toml</h3>
<pre><code class="language-toml line-numbers"># frps.toml —— 服务端配置
bindPort = 7000                  # frpc 连接 frps 的控制端口

auth.method = "token"
auth.token = "请换成32位以上随机字符串"   # 两端必须一致，相当于连接密码

# HTTP / HTTPS 反向代理端口
vhostHTTPPort = 8080
vhostHTTPSPort = 8443

# 子域名模式：*.example.com 都由这台 frps 接管
subDomainHost = "example.com"

# 管理面板（可选；生产环境建议只监听本机 + 强密码）
[webServer]
addr = "127.0.0.1"
port = 7500
user = "admin"
password = "请换成强密码"
</code></pre>
<h3>3. 放行防火墙并设开机自启</h3>
<p>云服务器安全组放行 <code>7000</code>、<code>8080</code>、<code>8443</code>（以及后面要用到的 remotePort）。服务器本机防火墙配置可参考<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/75/">Debian 关闭防火墙终极指南：UFW, Firewalld, Iptables 命令详解</a>——注意是&#8221;按需放行&#8221;而不是全关。</p>
<pre><code class="language-ini line-numbers"># /etc/systemd/system/frps.service
[Unit]
Description=frp server
After=network.target

[Service]
Type=simple
User=nobody
ExecStart=/usr/local/bin/frps -c /etc/frp/frps.toml
Restart=on-failure
RestartSec=5s

[Install]
WantedBy=multi-user.target
</code></pre>
<pre><code class="language-bash line-numbers">sudo mkdir -p /etc/frp && sudo cp frps.toml /etc/frp/
sudo cp frps /usr/local/bin/
sudo systemctl enable --now frps
sudo systemctl status frps   # 确认 running
</code></pre>
<h2>四、frp 客户端配置（frpc，跑在树莓派/内网机器上）</h2>
<h3>1. 下载对应架构的版本</h3>
<p>树莓派是 ARM64，下载 <code>linux_arm64</code> 包（版本号同样以官方 Releases 为准）：</p>
<pre><code class="language-bash line-numbers">wget https://github.com/fatedier/frp/releases/download/v0.xx.x/frp_0.xx.x_linux_arm64.tar.gz
tar xzf frp_0.xx.x_linux_arm64.tar.gz
cd frp_0.xx.x_linux_arm64
</code></pre>
<h3>2. 编写 frpc.toml：三个最常用场景</h3>
<pre><code class="language-toml line-numbers"># frpc.toml —— 客户端配置
serverAddr = "frp.example.com"   # frps 的域名或公网 IP（配合 DDNS 见第六节）
serverPort = 7000
auth.token = "请换成32位以上随机字符串"   # 必须与 frps 一致

# 场景 1：把树莓派 SSH 暴露出去
[[proxies]]
name = "ssh"
type = "tcp"
localIP = "127.0.0.1"
localPort = 22
remotePort = 6000        # 外网执行 ssh -p 6000 pi@frp.example.com 即可登录

# 场景 2：把内网 Web 服务用域名暴露
[[proxies]]
name = "nas-web"
type = "http"
localPort = 5000
customDomains = ["nas.example.com"]

# 场景 3：点对点加密通道（流量不经过 frps 中转）
[[proxies]]
name = "secret-share"
type = "stcp"
localPort = 9000
sk = "再单独设一个强密码"
</code></pre>
<blockquote><p>
  stcp 模式需要在访问端也跑一个 frpc 做 visitor，公网上的陌生人连不上，适合&#8221;自己的两台设备之间传文件&#8221;。流量点对点直连，速度也更快。
</p></blockquote>
<h3>3. 测试连通性，再设开机自启</h3>
<pre><code class="language-bash line-numbers">./frpc -c frpc.toml   # 前台运行测试，看到 login to server success 即成功
</code></pre>
<p>确认成功后，用和 frps 同样的 systemd 模板做成服务（把 <code>frps</code> 换成 <code>frpc</code>、配置文件路径换成 <code>/etc/frp/frpc.toml</code>），<code>systemctl enable --now frpc</code> 即可。</p>
<blockquote><p>
  ⚠️ 版本注意事项：自 v0.50 起 frpc 与 frps 之间默认启用 TLS；v0.52 起配置格式从 INI 切换为 TOML。<strong>服务端与客户端请使用同一版本</strong>，跨大版本混用可能连不上。
</p></blockquote>
<h2>五、免费 SSL 证书申请：acme.sh + Let&#8217;s Encrypt（DNS-01 通配符）</h2>
<p>为什么要证书？frp 的 https 代理需要证书做 TLS 卸载，否则浏览器会报&#8221;不安全&#8221;。Let&#8217;s Encrypt 证书免费、90 天有效，配合 acme.sh 可全自动续期。</p>
<p>为什么用 DNS-01 验证？因为我们要申请 <code>*.example.com</code> <strong>通配符证书</strong>——一张证书覆盖 nas、pi、blog 等所有子域名，而<strong>通配符证书只能用 DNS 验证</strong>，HTTP 验证办不到。</p>
<h3>1. 安装 acme.sh</h3>
<pre><code class="language-bash line-numbers">curl https://get.acme.sh | sh -s email=你的邮箱@example.com
# 安装到 ~/.acme.sh，并自动添加每天检查续期的 cron 任务
</code></pre>
<h3>2. 用 Cloudflare API 申请通配符证书</h3>
<p>域名托管在 Cloudflare 最省事（免费套餐即可）。先在 Cloudflare 后台创建一个 API Token（权限：<code>Zone → DNS → Edit</code>，限定到你的域名），并记下 Zone ID：</p>
<pre><code class="language-bash line-numbers">export CF_Token="你的 Cloudflare API Token"
export CF_Zone_ID="你的 Zone ID"

~/.acme.sh/acme.sh --issue --dns dns_cf \
  -d "example.com" -d "*.example.com"
</code></pre>
<p>全程约 1 分钟：acme.sh 自动创建 <code>_acme-challenge</code> TXT 记录完成验证，然后自动删掉，<strong>全程不需要开放 80 端口</strong>。</p>
<h3>3. 安装证书并设置自动 reload</h3>
<pre><code class="language-bash line-numbers">~/.acme.sh/acme.sh --install-cert -d "example.com" \
  --key-file       /etc/frp/ssl/privkey.pem \
  --fullchain-file /etc/frp/ssl/fullchain.pem \
  --reloadcmd      "systemctl reload nginx"
</code></pre>
<h3>4. 在 frps 侧启用 HTTPS</h3>
<p>frps 的 <code>vhostHTTPSPort</code>（如 8443）接收 TLS 流量。常见做法是在 VPS 上用 Nginx 监听 443 并加载上面的证书，再反向代理到 frps 的 8443；简单场景也可以直接访问 <code>https://nas.example.com:8443</code>（记得安全组放行该端口）。</p>
<p>续期完全自动：acme.sh 的 cron 每天检查，证书到期前自动续签并执行 <code>--reloadcmd</code>。建议每月看一眼 cron 日志确认无异常。</p>
<h2>六、DDNS 教程：IP 会变，域名不能断</h2>
<p>frpc 配置里的 <code>serverAddr</code> 写的是 frps 的地址。如果 frps 所在的机器 IP 变化（家用宽带、VPS 更换），域名解析必须跟上，否则隧道全断。</p>
<blockquote><p>
  先说清楚：<strong>frp 客户端在内网、IP 经常变，完全不影响</strong>——因为是 frpc 主动向外建连。DDNS 主要是保证&#8221;你手里的域名&#8221;永远指向 frps 服务器。
</p></blockquote>

<h3>实战：NewFuture/DDNS（推荐）</h3>
<pre><code class="language-bash line-numbers">pip install ddns

# 以 Cloudflare 为例：每 5 分钟检查一次公网 IP，变化则更新解析

</code></pre>
<p>把命令加到 cron（<code>*/5 * * * *</code>）或做成 systemd timer 即可。之后无论 frps 的 IP 怎么变，<code>frp.example.com</code> 始终指向最新地址，家里所有 frpc 不用改任何配置。</p>
<h2>七、树莓派远程访问实战：SSH + VNC 一次配好</h2>
<p>把第四节的 frpc 跑在树莓派上（Raspberry Pi OS，记得用 <code>linux_arm64</code> 包）并设好开机自启，之后：</p>
<ol>
<li><strong>SSH 命令行</strong>：<code>ssh -p 6000 pi@frp.example.com</code>（端口就是 frpc.toml 里 <code>remotePort</code> 的值）。</li>
<li><strong>VNC 图形桌面</strong>：树莓派上开启 VNC（<code>sudo raspi-config</code> → Interface Options → VNC → Yes），frpc.toml 再加一条：
<pre><code class="language-toml line-numbers">[[proxies]]
name = "vnc"
type = "tcp"
localPort = 5900
remotePort = 5900
</code></pre>
<p>电脑上用 VNC Viewer 连接 `frp.example.com:5900`，就能看到树莓派桌面。
</li>
<li><strong>Web 服务</strong>（Home Assistant、Jellyfin 等）：用第五节的 http/https 代理 + 免费证书，直接 <code>https://ha.example.com</code> 访问，和在家里局域网打开一样。</li>
</ol>
<p>关于延迟：frp 多了一跳中转，SSH/VNC 的体感延迟主要取决于 VPS 到你家的线路质量。选择离你近的 VPS 机房（如本站<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/542/">免费 VPS 攻略</a>里的区域选择建议），日常远程管理完全够用。</p>

<h2>九、FAQ</h2>
<p><strong>Q1：frp、Cloudflare Tunnel、Tailscale 到底选哪个？</strong><br />
看本站<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/intranet-penetration-guide/">内网穿透终极指南</a>的完整横评。一句话总结：想要完全自主可控、跑在自己 VPS 上选 frp；不想买服务器选 Cloudflare Tunnel；要组虚拟局域网、多设备互访选 Tailscale。</p>
<p><strong>Q2：家里没有公网 IP，能把 frps 跑在家里吗？</strong><br />
不能。frps 必须部署在有公网 IP 的机器上（或经 DDNS 解析到公网）。家里没公网 IP 的正确姿势：frps 放 VPS，frpc 放家里。完全不想买 VPS，请看<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/547/">无公网 IP 的 Cloudflare Tunnel / Tailscale 方案</a>。</p>
<p><strong>Q3：frpc 启动报 &#8220;login to server failed&#8221;？</strong><br />
99% 是两端 token 不一致，或服务端/客户端版本跨度太大。先核对两边 token，再确认版本号一致。</p>
<p><strong>Q4：https 访问提示证书不受信任？</strong><br />
检查证书是否覆盖了你访问的子域名（注意通配符 <code>*.example.com</code> 不包含裸域，申请时 <code>-d</code> 要把裸域和通配符都写上）；确认 Nginx/反代加载的是 <code>fullchain.pem</code> 而不是只有证书本身。</p>
<p><strong>Q5：acme.sh 申请通配符证书失败？</strong><br />
先检查 CF_Token 是否有对应 Zone 的 DNS Edit 权限；再确认域名 NS 确实托管在 Cloudflare。DNS 生效有延迟，失败后等几分钟再重试。</p>
<p><strong>Q6：树莓派重启后 frpc 没有自启？</strong><br />
检查 systemd unit 是否写了 <code>After=network-online.target</code>（网络没就绪 frpc 会连不上，配合 <code>Restart=on-failure</code> 兜底）；用 <code>journalctl -u frpc -f</code> 看实时日志定位。</p>
<p><strong>Q7：DDNS 更新了，域名还是解析到旧 IP？</strong><br />
DNS 有 TTL 缓存，把记录的 TTL 设小一点（如 300 秒）；用 <code>dig frp.example.com</code> 确认权威解析已更新，再等本地缓存过期。</p>
