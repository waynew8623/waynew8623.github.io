<h2>一、PicGo 是什么？为什么要用它</h2>
<p>PicGo 是一个开源的图床上传工具（GitHub 星数常年领先同类项目），支持 Windows / macOS / Linux。它本身不是存储服务，而是一个&#8221;上传管家&#8221;：把图片从你电脑送到任何一家对象存储，并返回 Markdown 外链。</p>
<p>它的核心优势是<strong>图床可切换</strong>：今天用 R2 明天想换 OSS，不用改写作习惯，换个配置就行。配合插件生态，还能做水印、重命名、压缩等自动化处理。</p>
<blockquote><p>
  <strong>2026 年重要变化</strong>：PicGo 已升级到 <strong>v3.0.2</strong>（本文核实时的最新版本），UI 全面重写，支持明暗主题，内置官方图床 <strong>PicGo Cloud</strong>（注册即享 200 个文件 + 500MB 免费额度）并成为新的默认图床（原默认 SM.MS 退居可选）；密钥保存后不再可明文查看，配置时请一次填对。
</p></blockquote>
<p>如果你此前跟着本站的 <a class="wp-editor-md-post-content-link" href="https://waynetalk.com/546/">Cloudflare R2 + PicGo 零成本图床方案</a> 搭过 R2，那本文相当于它的&#8221;配置手册升级版&#8221;：不只 R2，OSS、COS、S3 兼容服务一次配齐。</p>
<h2>二、安装与基础配置（3 步搞定）</h2>
<h3>1. 下载安装</h3>
<ol>
<li>GitHub <code>Molunerfinn/PicGo</code> 的 Releases 页面下载对应安装包；国内下载慢可用官方镜像站 <code>release.picgo.app</code>（Windows / macOS / Linux，含 x64 与 ARM64）；</li>
<li><strong>版本选择</strong>：直接装 v3.x 最新版。老版本（2.x）教程的菜单位置可能略有差异，但图床参数通用。</li>
</ol>
<h3>2. 安装插件（按需）</h3>
<p>在左侧「插件设置」搜索插件名，点击安装。后续章节会列出各图床是否需要插件，总体原则：</p>
<ul>
<li><strong>无需插件</strong>：阿里云 OSS、腾讯云 COS、Amazon S3、PicGo Cloud（PicGo 2.3+ / v3 已内置）</li>
<li><strong>需要插件</strong>：Cloudflare R2 → <code>@tianlelyd/picgo-plugin-cloudflare-r2</code>（作者 <code>tianleyd</code>），装错插件会导致配置项对不上号</li>
</ul>
<h3>3. 设为默认图床与快捷键</h3>
<ol>
<li>进入「图床设置」，填好某一家参数后点「确定」→「设为默认图床」；</li>
<li>在「PicGo 设置」里确认上传快捷键（默认截图上传 <code>Ctrl+Shift+P</code>，Windows），以及「开机自启」「上传前压缩」等选项；</li>
<li>到「上传区」拖一张图测试：上传成功后链接会自动复制到剪贴板，浏览器打开能访问即配置正确。</li>
</ol>

<h2>四、图床配置详解（一家一节）</h2>
<h3>4.1 Cloudflare R2：零成本首选</h3>
<p>R2 是 Cloudflare 的对象存储，S3 协议兼容，免费额度对个人博客非常充裕。PicGo <strong>默认不支持 R2</strong>，必须先装插件。</p>
<p><strong>第一步：准备 R2 侧的三个值</strong></p>
<ol>
<li>Cloudflare 控制台 →「存储与数据库」→ R2 → 创建存储桶（如 <code>blog-images</code>）；</li>
<li>R2 首页 →「管理 R2 API 令牌」→ 创建令牌，权限选「对象读写」，绑定你的存储桶，有效期选「永久」；</li>
<li>一次性展示的 <strong>Access Key ID、Secret Access Key、Endpoint</strong> 立即保存（Endpoint 形如 <code>https://&lt;账户ID&gt;.r2.cloudflarestorage.com</code>）；</li>
<li>存储桶设置 →「自定义域」绑定自己的域名（如 <code>https://img.example.com</code>），或用 Cloudflare 提供的 <code>pub-xxxx.r2.dev</code> 开发域名。</li>
</ol>
<p><strong>第二步：安装 R2 插件</strong></p>
<p>插件设置 → 搜索 <code>@tianlelyd/picgo-plugin-cloudflare-r2</code>，认准作者 <strong><code>tianleyd</code></strong>，点击安装（不是另一个同名 <code>cloudflare-r2</code> 插件）。</p>
<p><strong>第三步：填参数</strong></p>
<table>
<thead>
<tr>
<th>配置项</th>
<th>填什么</th>
</tr>
</thead>
<tbody>
<tr>
<td>Account ID</td>
<td>Cloudflare 仪表盘右侧的账户 ID</td>
</tr>
<tr>
<td>AccessKey ID</td>
<td>R2 API 令牌的访问密钥 ID</td>
</tr>
<tr>
<td>Secret Access Key</td>
<td>R2 API 令牌的机密访问密钥</td>
</tr>
<tr>
<td>Bucket Name</td>
<td>存储桶名，如 <code>blog-images</code></td>
</tr>
<tr>

<td>公开访问域名，如 <code>https://img.example.com</code>（<strong>必填，否则返回的外链打不开</strong>）</td>
</tr>

<h3>4.3 阿里云 OSS：国内访问最稳</h3>
<p>PicGo 从 <strong>2.3.0 开始已内置阿里云 OSS</strong>，2.x/3.x 用户无需装插件。适合国内访问量较大的博客，或已有阿里云账号的用户。</p>
<p><strong>第一步：OSS 侧准备</strong></p>
<ol>
<li>OSS 控制台创建 Bucket：标准存储，读写权限选<strong>公共读</strong>，冗余类型选<strong>本地冗余（LRS）</strong>（个人用足够，比同城冗余便宜约 25%）；</li>
<li>在 Bucket 概览页记下 <strong>Endpoint（地域节点）</strong>，如华东 1（上海）是 <code>oss-cn-shanghai</code>；</li>
<li>RAM 控制台创建 AccessKey（建议只授予 OSS 相关权限），保存 KeyId 与 KeySecret。</li>
</ol>

<h3>4.4 腾讯云 COS：国内用户的另一个选择</h3>

<h2>五、Typora / Obsidian 联动：写作流最后一公里</h2>
<p>图床配好后，真正的效率提升来自与写作工具的联动。</p>
<h3>Typora：粘贴即上传</h3>
<ol>
<li>Typora → <code>文件</code> → <code>偏好设置</code> → <code>图像</code>；</li>
<li>「插入图片时…」选 <strong>上传图片</strong>，「上传服务」选 <strong>PicGo (app)</strong>；</li>
<li>「PicGo 路径」填安装路径：Windows 如 <code>C:\Users\&lt;用户名&gt;\AppData\Local\Programs\PicGo\PicGo.exe</code>，macOS 直接从&#8221;应用程序&#8221;文件夹把 <code>PicGo.app</code> 拖入输入框；</li>
<li>点「验证图片上传选项」，通过后截图/Ctrl+V 粘贴的图片会自动上传并替换为外链。</li>
</ol>
<h3>Obsidian：Image auto upload 插件</h3>
<ol>
<li>Obsidian 设置 → 第三方插件 → 关闭安全模式 → 浏览社区插件，搜索 <strong>Image auto upload</strong> 安装启用；</li>
<li>插件设置里指定调用 PicGo（需 PicGo 开启 Server，或直接调用 PicGo CLI）；</li>
<li>之后在笔记里粘贴截图，图片自动上传到图床并替换链接，跨设备同步不再丢失图片。</li>
</ol>
<p>如果你正在用 Hugo/Hexo + Cloudflare Pages 搭博客（本站有<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/543/">零成本建站全流程教程</a>），这套「Typora 写稿 → PicGo 上传 → Git 推送」的流程会非常顺滑。</p>

<h2>七、FAQ</h2>
<p><strong>Q1：PicGo 新装应该选 2.x 还是 3.x？</strong><br />
A：直接装最新的 v3.0.2。v3 是 2026 年的正式大版本：UI 重写、明暗主题、内置 PicGo Cloud 官方图床（注册送 200 文件/500MB 免费额度）、密钥保存后自动掩码。老教程截图是 2.x 界面，菜单位置略有不同，但图床参数完全通用。</p>
<p><strong>Q2：R2 一定要装插件吗？</strong><br />
A：两种走法：① 装 <code>@tianlelyd/picgo-plugin-cloudflare-r2</code>（作者 tianleyd）插件，配置项最贴合 R2；② 不装插件，用内置「Amazon S3」图床，填 R2 的 Endpoint + 密钥同样能用。R2 本质是 S3 兼容协议，两条路通向同一个终点。</p>
<p><strong>Q3：个人博客选 R2 还是阿里云 OSS？</strong><br />
A：追求零成本选 R2（免费额度对个人博客足够）；看重国内访问速度、有一定访问量选 OSS（通常一年几十元）。PicGo 支持保存多套图床配置，随时切换默认图床，两者可以并存。</p>
<p><strong>Q4：图片链接可以用自定义域名吗？</strong><br />
A：可以，而且强烈建议。R2、OSS、COS 都支持在 PicGo 配置里填 Custom Domain，前提是先在对象存储控制台绑定域名并做好 CNAME/DNS 解析。将来换图床只需改解析，不用批量替换文章里的链接。</p>
<p><strong>Q5：密钥泄露了怎么办？</strong><br />
A：立即到云厂商控制台（阿里云 RAM / 腾讯云 CAM / Cloudflare API 令牌）删除或禁用该密钥，重新创建一对并更新 PicGo 配置。注意 PicGo 配置文件是用户目录下的明文 JSON，不要发给别人或上传到公开仓库。</p>
<p><strong>Q6：除了 R2/OSS/COS，PicGo 还支持哪些图床？</strong><br />
A：内置的有 SM.MS、Imgur、七牛云、又拍云、GitHub、Gitee、Amazon S3、腾讯云 COS、阿里云 OSS 等，插件市场还有更多。选型原则：国内访问选 OSS/COS，零成本选 R2，已有服务器选自建 S3。</p>
<h2>八、总结</h2>
<p>PicGo 图床配置的核心流程只有四步：<strong>选一家图床 → 拿到密钥三件套 → 在 PicGo 里填参数表 → 设为默认图床并测试</strong>。R2 适合零成本起步，OSS/COS 适合国内访问（PicGo 已内置，直接填表即可）。</p>
