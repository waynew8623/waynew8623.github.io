<h2>1. 为什么说 Sing-box 是当前最具统治力的代理核心？</h2>
<p>在过去很长一段时间内，科学上网生态由 v2ray-core、Xray-core 以及 <a href="https://waynetalk.com/clash-tutorial-beginners/">Clash</a> 鼎足而立。但随着 Clash 原版停更以及新型协议（如 <a href="https://waynetalk.com/699/">Hysteria 2</a>、<a href="https://waynetalk.com/705/">TUIC v5</a>）的涌现，传统内核面临代码臃肿与拓展性瓶颈。</p>
<p><strong>Sing-box</strong>（由 SagerNet 团队打造）凭借以下技术创新成为了<a href="https://waynetalk.com/sing-box-tutorial/">跨平台首选</a>：<br />1. <strong>全协议大一统</strong>：原生态集成 <a href="https://waynetalk.com/708/">Shadowsocks</a>、VMess、VLESS、Trojan、Hysteria 2、TUIC、WireGuard、Tor 等近乎所有协议，无需外挂第三方插件。<br />2. <strong>极低资源消耗</strong>：相比传统 Java 或重量级 Electron 客户端，Sing-box 内存常驻仅为 20MB~50MB，极其适合部署在<a href="https://waynetalk.com/704/">软路由</a>（OpenWrt）或移动设备上。<br />3. <strong>先进的路由规则集（Rule-Set）架构</strong>：</p>
<ul>
<li>传统客户端使用巨大的文本列表匹配域名和 IP，匹配时严重消耗 CPU；</li>
<li>Sing-box 引入了预编译的二进制规则集（<code>.srs</code>），支持毫秒级内存加载与基数树（Radix Tree）高速查询。</li>
</ul>
<p>4. <strong>原生跨平台 Tun 驱动（gVisor / Mixed）</strong>：</p>
<ul>
<li>彻底摆脱 HTTP 系统代理无法代理终端命令行（Git/SSH）和游戏 UDP 流量的痛点。</li>
</ul>

<h2>2. Sing-box 核心配置架构解构</h2>
<p>Sing-box 采用模块化的 JSON 结构，主要包含 5 大核心区块：</p>
<pre><code class="language-sing-box config.json">├── log (日志设置)
├── dns (DNS 策略与分流服务器)
├── inbounds (入站流量：Tun、Socks5、Mixed、Redirect)
├── outbounds (出站节点：直连、代理、节点选择组、URLTest)
└── route (路由逻辑：规则集匹配、域名分流、IP 分流)
</code></pre>

<h2>5. 高性能 Rule-Set（二进制规则集）进阶技巧</h2>
<p>传统代理经常需要定期更新 <code>geosite.dat</code> 和 <code>geoip.dat</code>，这两个文件体积可达数十兆，加载时消耗大量内存。</p>
<h3>Sing-box SRS 规则集的两大杀手锏：</h3>
<ol>
<li><strong>按需远程下载与持久缓存</strong>：</li>
</ol>
<ul>
<li>只需要声明规则集 URL，Sing-box 会在后台通过指定的出站通道（如 <code>download_detour: "proxy"</code>）静默下载，并缓存到本地磁盘。</li>
</ul>
<ol start="2">
<li><strong>零延时解析</strong>：</li>
</ol>
<ul>
<li>二进制编码的 <code>.srs</code> 文件可以直接做内存映射，启动瞬间完成数十万条规则的加载，内存开销减少 70% 以上。</li>
</ul>

<h2>6. 常见故障排查（FAQ）</h2>
<h3>Q1: 开启 Tun 模式后，内网 NAS 和打印机无法访问怎么办？</h3>
<ul>
<li><strong>解答</strong>：在 <code>route.rules</code> 的顶部加入私有 IP 直连规则：</li>
</ul>
<pre><code class="language-json">  {
    "ip_is_private": true,
    "outbound": "direct"
  }
  </code></pre>
<p>同时确保 <code>auto_detect_interface: true</code>，以便 Sing-box 正确识别物理默认网关。</p>
<h3>Q2: 出现 DNS 回环死锁（DNS Loop）该如何定位？</h3>
<ul>
<li><strong>排查步骤</strong>：如果把 DNS 查询的 <code>detour</code> 设定为某个代理节点，而该节点的 <code>server</code> 是域名且未配置 Bootstrap DNS，就会出现“为了连上代理需要解析域名，而解析域名又依赖代理”的死循环。</li>
<li><strong>最佳实践</strong>：在 <code>outbounds</code> 中的节点如果使用域名连接，必须为 Sing-box 指定一个无需代理的直连 DNS 服务器（如 <code>223.5.5.5</code> 或 <code>119.29.29.29</code>）。</li>
</ul>
