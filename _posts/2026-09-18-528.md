<h2 class="wp-block-heading">架构</h2>

<pre><code>用户 → Telegram → n8n(Webhook)
                  → 取上下文（按 chatId）
                  → 意图判断（普通问答 / 查订单 / 转人工）
                  → 调模型 or 调业务 API
                  → 回写上下文
                  → 回复 Telegram
</code></pre>

<h2 class="wp-block-heading">第一步：创建 Telegram Bot 并接 Webhook</h2>

<p class="wp-block-paragraph">@BotFather 创建 Bot 拿到 Token，在 n8n 用 <strong>Telegram Trigger</strong> 节点：</p>

<ul class="wp-block-list">
<li>认证：填入 Bot Token</li>
<li>Updates：<code>message</code></li>
<li>Webhook 模式（n8n 会自动注册 Webhook 到 Telegram，需公网可访问）</li>
</ul>

<p class="wp-block-paragraph">如需手动注册：</p>

<pre><code>POST https://api.telegram.org/bot<TOKEN>/setWebhook
Body: { "url": "https://n8n.example.com/webhook/telegram-bot" }
</code></pre>

<h2 class="wp-block-heading">第二步：维护用户对话上下文</h2>

<p class="wp-block-paragraph">多轮对话的关键是「记住历史」。按 <code>chatId</code> 存上下文，生产用 <strong>Postgres</strong> 或 <strong>Redis</strong>，演示用 n8n 静态数据：</p>

<pre><code class="language-javascript">// 读取历史
const chatId = <span class="katex math inline">json.message.chat.id;
const store =</span>getWorkflowStaticData('global').ctx || {};
const history = store[chatId] || [];

// 把本轮用户消息加入
history.push({ role: 'user', content: $json.message.text });

// 调用模型（示意：拼 messages）
const messages = [
  { role: 'system', content: '你是某公司客服，语气专业友好，未知信息请说转人工。' },
  ...history.slice(-10) // 仅保留最近 10 轮
];
return [{ json: { chatId, messages } }];
</code></pre>

<p class="wp-block-paragraph">回复后把 assistant 内容也写回 <code>store[chatId]</code>，实现记忆。</p>

<blockquote class="is-layout-flow wp-block-quote-is-layout-flow">
<p>生产建议：上下文存 Redis（TTL 设 30 分钟自动失效），避免内存膨胀与重启丢失。</p>
</blockquote>

<h2 class="wp-block-heading">第三步：挂载自定义业务 API（查订单）</h2>

<p class="wp-block-paragraph">用 <strong>IF / Switch</strong> 节点做意图分类（简单场景用关键词，复杂用模型分类）。命中「查订单」走 API：</p>

<pre><code>POST https://api.yoursite.com/order/status
Headers: Authorization: Bearer {{ <span class="katex math inline">env.ORDER_API_KEY }}
Body: { "orderId": "{{</span>json.orderId }}" }
</code></pre>

<p class="wp-block-paragraph">再用 <strong>Set</strong> 节点把订单状态拼进提示词，让模型用自然语言回复：</p>

<pre><code>你的订单 {{ order.no }} 状态：{{ order.status }}，预计 {{ order.eta }} 送达。
</code></pre>

<p class="wp-block-paragraph">意图识别正则示例：</p>

<pre><code class="language-regex">订单|查单|express|tracking|物流
</code></pre>

<h2 class="wp-block-heading">第四步：调用大模型生成回复</h2>

<p class="wp-block-paragraph">用 <strong>HTTP Request</strong> 调<a href="https://waynetalk.com/544/">兼容 OpenAI 协议的接口</a>：</p>

<pre><code>POST https://your-llm/v1/chat/completions
Headers: Authorization: Bearer {{ <span class="katex math inline">env.LLM_KEY }}
Body:
{
  "model": "your-model",
  "messages": {{</span>json.messages }},
  "temperature": 0.5,
  "max_tokens": 800
}
</code></pre>

<p class="wp-block-paragraph">解析 <code>choices[0].message.content</code> 为 <code>reply</code>。</p>

<blockquote class="is-layout-flow wp-block-quote-is-layout-flow">
<p>n8n 1.x 及以上版本可直接用 <strong>LangChain</strong> 节点（Chat Model + Memory + 工具节点），把「上下文记忆」「工具调用」做成可视化链，比手写 JSON 更稳。</p>
</blockquote>

<h2 class="wp-block-heading">第五步：工具调用（Function Calling）进阶</h2>

<p class="wp-block-paragraph"><a href="https://waynetalk.com/539/">让模型自己决定调哪个 API</a>：定义 tools 描述，模型返回 <code>tool_calls</code> 时，n8n 用 <strong>Switch</strong> 路由到对应 HTTP Request，执行后把结果回填再二次生成。典型工具：</p>

<ul class="wp-block-list">
<li><code>query_order(orderId)</code> —— 查订单</li>
<li><code>check_stock(sku)</code> —— 查库存</li>
<li><code>create_ticket(content)</code> —— 建工单</li>
</ul>

<h2 class="wp-block-heading">第六步：转人工与未命中兜底</h2>

<ul class="wp-block-list">
<li>命中关键词「人工」「投诉」→ 直接转人工群（Telegram 节点通知客服）。</li>
<li>模型判定无法回答 → 自动建工单并回复「已记录，专员稍后联系」。</li>
<li>超时无响应 → 定时任务扫描未结会话提醒客服。</li>
</ul>

<h2 class="wp-block-heading">第七步：安全与限额</h2>

<ul class="wp-block-list">
<li><strong>鉴权</strong>：Telegram Webhook 本身有 Token 校验，但 n8n 端点建议加 <code>Header Auth</code>。</li>
<li><strong>限流</strong>：单 chatId 每分钟限制请求数，防刷。</li>
<li><strong>内容审核</strong>：对用户消息做敏感词过滤，避免模型被诱导输出不当内容。</li>
<li><strong>数据</strong>：对话日志仅保留必要时长，遵守隐私合规。</li>
</ul>

<h2 class="wp-block-heading">完整节点清单（可导出的工作流）</h2>

<p class="wp-block-paragraph"><code>Telegram Trigger → Code(取上下文) → IF(意图) → HTTP(业务API) / HTTP(模型) → Code(写回上下文) → Telegram(回复)</code>。导出 JSON 后团队可复用，注意替换 Token 与 API Key 为环境变量。</p>

<h2 class="wp-block-heading">总结</h2>

<p class="wp-block-paragraph">n8n 让「会调你内部系统的 AI 客服」不再是大厂专利。可视化编排 + 上下文记忆 + 工具调用，中小企业也能在一下午内上线一个能查订单、能多轮对话的 Telegram 客服。</p>

<h2 class="wp-block-heading">FAQ</h2>

<p class="wp-block-paragraph"><strong>Q1：上下文记忆需要额外数据库吗？</strong><br />
演示可用 n8n 静态数据，但重启会丢。生产强烈建议用 Redis/Postgres，按 chatId 存并设 TTL。</p>

<p class="wp-block-paragraph"><strong>Q2：模型必须用 OpenAI 吗？</strong><br />
不必。任何兼容 Chat Completions 协议的端点（本地 Ollama、自建 vLLM、国产大模型网关）都能通过 HTTP Request 调用，数据可不出内网。</p>

<p class="wp-block-paragraph"><strong>Q3：用户发图片/语音能处理吗？</strong><br />
Telegram Trigger 能收到图片、语音等附件。图片可接 OCR/Vision 模型，语音可先转写再处理；n8n 的二进制与 HTTP 节点都支持转发文件。</p>
