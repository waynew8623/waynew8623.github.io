<h2>一、先理解&#8221;穿透&#8221;的三种姿势</h2>
<p>选型之前，先搞清内网穿透的三种技术路线，选错路线后面全是弯路：</p>
<ul>
<li><strong>反向隧道（Cloudflare Tunnel）</strong>：内网机器主动向外建立长连接，外部通过服务商的边缘网络访问。家里<strong>不开放任何入站端口</strong>，安全性最高。</li>
<li><strong>端口转发（frp）</strong>：同样是内网主动连向一台有公网 IP 的中转服务器，服务器把指定端口的流量转发回来。支持 TCP/UDP 全协议，最灵活，但需要你自己准备一台中转 VPS。</li>
<li><strong>虚拟组网（Tailscale / ZeroTier）</strong>：把分散在各地的设备拉进一张虚拟局域网，设备之间像在同一个路由器下一样直接互访。适合&#8221;我想 SSH 到家里机器、访问 NAS 文件&#8221;的场景。</li>
</ul>
<p>一句话：<strong>对外发布给别人看 → 反向隧道/端口转发；自己多台设备互联 → 虚拟组网。</strong></p>

<h2>三、各方案一句话上手指南</h2>
<h3>1. frp：最灵活的自建穿透</h3>
<p>frp（Fast Reverse Proxy）是 GitHub 上最知名的开源内网穿透工具，分服务端 <code>frps</code>（放有公网 IP 的 VPS 上）和客户端 <code>frpc</code>（放家里机器上）两部分。注意：<strong>新版配置已改用 TOML 格式</strong>，旧教程里的 ini 写法会报 deprecated 警告。</p>
<pre><code class="language-toml line-numbers"># frps.toml（公网 VPS 上）
bindPort = 7000
auth.token = "换成你自己的强密码"

# frpc.toml（家里机器上）
serverAddr = "你的VPS公网IP"
serverPort = 7000
auth.token = "换成你自己的强密码"

[[proxies]]
name = "nas-web"
type = "tcp"
localIP = "127.0.0.1"
localPort = 5000      # 家里 NAS 的 Web 端口
remotePort = 6000     # 通过 VPS_IP:6000 访问
</code></pre>
<p>启动后，访问 <code>你的VPS公网IP:6000</code> 就等于访问家里 NAS 的 5000 端口。frp 还支持 HTTP/HTTPS 域名分流、TCP 多路复用、流量压缩，甚至实验性的 P2P 模式。</p>
<p>没有 VPS？本站的《<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/542/">永久免费云服务器盘点：Oracle Cloud 保活与网络调优全攻略</a>》介绍的免费 VPS 足够跑 frps；也可以先用社区运营的免费 frp 服务商体验（带宽和流量有限，仅适合轻量测试）。</p>
<h3>2. Cloudflare Tunnel：最安全的对外发布</h3>
<p>适合场景：你想用 <code>nas.你的域名.com</code> 从任何地方访问家里的服务，且<strong>一分钱不想花、一个入站端口不想开</strong>。</p>
<pre><code class="language-bash line-numbers"># 家里服务器安装 cloudflared（Debian/Ubuntu）
wget -q https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
sudo dpkg -i cloudflared-linux-amd64.deb

# 登录并创建隧道
cloudflared tunnel login
cloudflared tunnel create home-tunnel
cloudflared tunnel route dns home-tunnel nas.你的域名.com
</code></pre>
<p>然后写个 <code>config.yml</code> 把域名指向本地服务，<code>cloudflared tunnel run home-tunnel</code> 常驻即可。全程流量经 Cloudflare 边缘，还能叠加 WAF 和 Zero Trust Access 登录保护。详细步骤见本站旧文《<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/547/">无公网 IP 方案</a>》第三节。</p>
<p>注意：Tunnel 只适合 HTTP/HTTPS 类 Web 服务，不适合游戏、SSH 这类任意 TCP 流量；且域名需要托管在 Cloudflare（本站《<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/543/">0 元搭建个人独立博客：Cloudflare Pages + Hugo/Hexo + 免费域名绑定</a>》里有 Cloudflare 的玩法）。</p>
<h3>3. Tailscale：最顺滑的异地组网</h3>
<p>适合场景：不止一个 Web 服务，你想从手机、笔记本<strong>直接 SSH 到家里机器、访问 NAS 的 SMB 文件共享、串流游戏画面</strong>。</p>
<pre><code class="language-bash line-numbers"># 家里 Linux 机器
curl -fsSL https://tailscale.com/install.sh | sh
sudo tailscale up   # 浏览器打开链接登录即可
</code></pre>
<p>记下这台机器的 Tailscale 虚拟 IP（如 <code>100.x.x.x</code>），从任何已登录的设备直接 <code>ssh user@100.x.x.x</code> 就行，就像在同一个局域网。进阶玩法是在家里路由器或 NAS 上开 <strong>Subnet Router（子网路由）</strong>，让网内设备直接访问整个 <code>192.168.x.x</code> 家庭局域网——连不支持装客户端的设备（如打印机、摄像头）都能被访问到。</p>
<p>个人免费档覆盖 3 个用户、100 台设备，家庭场景绰绰有余。基于 WireGuard，延迟低、体验顺滑，是四个方案里上手最快的。</p>
<h3>4. ZeroTier：经典的虚拟局域网</h3>
<p>思路与 Tailscale 类似：创建一个虚拟网络（Network ID），把设备加进来，分配虚拟 IP，设备间直连通信。</p>
<pre><code class="language-bash line-numbers">curl -s https://install.zerotier.com | sudo bash
sudo zerotier-cli join <你的网络ID>
# 然后去 ZeroTier 管理后台授权该节点
</code></pre>
<p>适合喜欢&#8221;一个网络 ID 拉起所有设备&#8221;的老玩家。免费版支持 25 台设备以内，超量需要付费或自建控制器（Moon 节点）。相比 Tailscale，它的客户端更轻量、协议更开放，但管理后台和移动端体验稍逊一筹。</p>
<h2>四、按场景推荐：四类人四种起手式</h2>
<h3>场景 1：NAS 远程访问（最常见）</h3>
<p><strong>首选 Tailscale</strong>。NAS 厂商（群晖、威联通、飞牛）大多有官方或社区套件，装好登录就能在外面像在家里一样访问文件、照片、影音库。本站《<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/551/">NAS / VPS 媒体库搭建：Docker 一键部署 Emby/Jellyfin</a>》搭好的影音库，配上 Tailscale 就是随身携带的私人影院。</p>
<p>如果只想把 NAS 的某个 Web 面板分享给家人用域名访问，<strong>Cloudflare Tunnel</strong> 更合适，不用给每个人装客户端。</p>
<h3>场景 2：微信开发调试（需要公网回调 URL）</h3>
<p>微信公众号、小程序开发时，微信服务器要能回调到你的本地开发机。<strong>首选 frp 的 HTTP 代理或 Cloudflare Tunnel</strong>，两者都能给你一个公网可访问的地址填进微信后台。frp 的好处是端口和域名完全自己掌控，适合长期调试；Tunnel 的好处是零成本、自动 HTTPS。</p>
<h3>场景 3：异地组网（多地设备互联）</h3>
<p>比如老家父母的电脑、你手里的笔记本、云上的一台 VPS 想组成一张网互相访问。<strong>首选 Tailscale</strong>，100 台设备免费额度、WireGuard 内核、打洞成功率高；偏好开源可控的选 ZeroTier（可自建控制器彻底摆脱官方服务器）。</p>
<h3>场景 4：游戏联机 / 开服</h3>
<p>和朋友联机玩 Minecraft、泰拉瑞亚这类需要直连的游戏：<strong>有 VPS 就用 frp</strong>，把游戏端口（如 25565）映射出去，延迟只取决于你的 VPS 线路，最稳定；<strong>没 VPS 就用 Tailscale/ZeroTier</strong>，大家加入同一张虚拟网，用虚拟 IP 直连，零成本开黑。</p>
<h2>五、免费内网穿透方案：怎么选才不踩坑</h2>
<p>搜&#8221;免费内网穿透方案&#8221;的人，核心诉求是<strong>零成本</strong>。把免费路线捋清楚：</p>
<ol>
<li><strong>完全零成本</strong>：Cloudflare Tunnel（要自备域名，免费域名也行）/ Tailscale / ZeroTier，三者都不需要你花一分钱，也不需要公网 IP。</li>
<li><strong>frp 的&#8221;免费&#8221;有前提</strong>：软件本身开源免费，但中转需要一台有公网 IP 的服务器。用免费 VPS（如 Oracle Cloud 免费层）可以做到零成本；用社区免费 frp 服务商则要注意带宽和流量限制，只适合测试。</li>
<li><strong>别为&#8221;免费&#8221;牺牲安全</strong>：免费 frp 服务商的流量经过第三方节点，敏感服务（NAS 管理后台、摄像头）务必走 TLS/加登录认证，或者干脆用 Tailscale 这类端到端加密的方案。</li>
</ol>
<h2>六、安全注意事项</h2>
<p>内网穿透的本质是&#8221;把家门打开一条缝&#8221;，安全清单请逐项检查：</p>
<ul>
<li><strong>最小暴露原则</strong>：能放在 Tailscale 私有网里的服务，就不要用 Tunnel/frp 公开到互联网。</li>
<li><strong>公开服务必须加认证</strong>：Cloudflare Tunnel 务必叠加 Access 登录保护；frp 映射的管理后台务必设强密码，token 用高强度随机串。</li>
<li><strong>frp 传输加密</strong>：0.50.0 之后版本默认开启 TLS，<strong>不要用老版本</strong>，也不要图省事关掉加密。</li>
<li><strong>及时更新</strong>：家里 NAS、树莓派的系统和穿透客户端保持最新，避免已知漏洞被利用。</li>
<li><strong>合规边界</strong>：这些工具只用于合法的远程访问与自组网，不得用于绕过网络管控、非法代理、传播违规内容等违法用途。</li>
</ul>
<h2>七、FAQ</h2>
<p><strong>Q1：没有公网 IP，到底能不能远程访问家里 NAS？</strong><br />
A：能，这正是内网穿透解决的问题。最省事的是 Tailscale：NAS 和手机都装客户端登录，就像在同一局域网；想用域名访问则用 Cloudflare Tunnel。具体步骤见本站旧文《<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/547/">无公网 IP 方案</a>》。</p>
<p><strong>Q2：完全免费的内网穿透方案有哪些？</strong><br />
A：Cloudflare Tunnel、Tailscale（个人免费）、ZeroTier（25 台以内免费）都是官方免费、不需要公网 IP 的方案；frp 软件免费，但需要一台有公网 IP 的 VPS 做中转，配合免费 VPS 也能做到零成本。</p>
<p><strong>Q3：frp 和 Cloudflare Tunnel 选哪个？</strong><br />
A：frp 更灵活：支持 TCP/UDP 任意协议、端口完全自控，适合游戏开服、SSH、微信调试；Cloudflare Tunnel 更省心：零入站端口、自带 CDN 和 WAF，适合对外发布 Web 服务。两者可以共存。</p>
<p><strong>Q4：Tailscale 和 ZeroTier 哪个更好？</strong><br />
A：新手选 Tailscale：WireGuard 内核、100 台设备免费、客户端体验好；偏好开源可控、想自建控制器的选 ZeroTier。日常家用两者体验接近。</p>
<p><strong>Q5：内网穿透速度慢怎么办？</strong><br />
A：先定位瓶颈：Tailscale/ZeroTier 优先 P2P 直连，被 NAT 阻断时会走官方中继变慢，可尝试在路由器开启 UPnP 改善打洞；frp 的速度取决于你的 VPS 带宽，换线路更好的 VPS 最直接；Cloudflare Tunnel 取决于你的上行带宽和 Cloudflare 边缘节点质量。</p>
<p><strong>Q6：用内网穿透把 NAS 公开到互联网安全吗？</strong><br />
A：分情况。Cloudflare Tunnel + Access 登录保护是相对安全的；frp 直接映射端口则务必设强密码、开 TLS。最稳妥的是只通过 Tailscale 私网访问，不公开。记住最小暴露原则。</p>
<p><strong>Q7：微信开发本地调试，内网穿透怎么配？</strong><br />
A：用 frp 的 HTTP 类型代理或 Cloudflare Tunnel，把本地开发端口（如 8080）映射成公网可访问的地址（含自动 HTTPS），填到微信公众平台的服务器 URL 里即可，改代码实时生效。</p>
<h2>总结</h2>
<p>没有公网 IP 早已不是远程访问的障碍，关键是按场景选对工具：<strong>对外发布 Web 服务用 Cloudflare Tunnel（最安全、零入站端口），多台设备像局域网一样互联用 Tailscale（最顺滑），要完全自控、转发任意 TCP/UDP 流量用 frp（最灵活），偏好经典虚拟局域网用 ZeroTier</strong>。四款都有免费方案，个人家庭场景零成本即可跑通。</p>
<p>实战中它们经常组合使用：Tunnel 负责对外发布，Tailscale 负责私有管理，frp 负责特殊协议转发。记住三条底线——只暴露必要的服务、给公开服务加认证、合规使用。</p>
