<h3>1. Supabase：全栈小应用的&#8221;一条龙&#8221;</h3>
<p>开源的 Firebase 替代品，底层就是 PostgreSQL，打包了 Auth（登录）、Storage（文件）、Realtime（实时订阅）、Edge Functions。免费档约 500MB 数据库存储 + 1GB 文件存储 + 5 万月活用户，对个人项目足够。</p>
<p><strong>注意两点</strong>：免费项目闲置约一周会被暂停，需要手动恢复；想做持续运行的服务，要么保持活跃，要么升级付费。适合&#8221;想要完整后端、不想自己拼服务&#8221;的场景，一个免费项目就能跑起带登录的小应用。</p>
<h3>2. Neon：Serverless Postgres，闲置零成本</h3>
<p>最大卖点是<strong>缩容到零</strong>：没流量时计算自动归零，冷启动约几百毫秒；以及<strong>数据库分支</strong>——为每个 PR 拉一个数据库做预览环境，体验极佳。免费层每项目约 0.5GB，可建多个项目，无需信用卡。</p>
<p>适合 Serverless 部署（Vercel / Cloudflare Workers / 函数计算）场景：数据库随应用一起按量伸缩，访问不规律的 side project 几乎零成本。0.5GB 存储偏小是短板，数据量大了再考虑付费。</p>
<h3>3. Turso：免费档的&#8221;额度之王&#8221;</h3>
<p>基于 libSQL（SQLite 分支）的边缘数据库，免费档约 5GB 存储、约 100 个数据库、每月约 5 亿行读取——按量算是三家里最慷慨的。全球 300+ 边缘节点，读延迟极低，还支持嵌入式副本（把库同步到本地文件，微秒级读取）。</p>
<p>代价是<strong>非 Postgres</strong>：生态和 SQL 方言是 SQLite 那套，如果你重度依赖 Postgres 特性（RLS、pgvector 等），迁移有成本。适合读多写少的内容站、API、多租户（database-per-tenant）架构。注意 Turso 在 2026 年初调整过缩容策略，具体以官网为准。</p>
<h3>4. 其他备选</h3>
<ul>
<li><strong>MongoDB Atlas（M0）</strong>：约 512MB 共享集群，文档型数据库的老牌免费档；学生包里还有它的额度加成，学生可叠加。</li>
<li><strong>Cloudflare D1</strong>：SQLite 跑在 Workers 上，绑定 Cloudflare 生态，适合纯 Serverless 的轻量场景。</li>
<li><strong>PlanetScale</strong>：再强调一次，<strong>免费档已于 2024 年 4 月移除</strong>，目前只有付费方案。看到&#8221;PlanetScale 免费 5GB&#8221;的旧教程请直接划过。</li>

<h2>三、选型建议：四类人四种起手式</h2>
<h3>1. 做全栈小应用 / 毕设 / 带登录的产品 → Supabase</h3>
<p>登录、数据库、文件存储、实时订阅一次配齐，原型开发速度最快。RLS 行级安全做多用户权限很省事。记得定期导出备份——免费档通常没有完整的自动备份。</p>
<h3>2. 玩 Serverless / 预览环境 / 访问不规律 → Neon</h3>
<p>Vercel + Neon 是经典组合：前端 Serverless、数据库缩容到零，闲置不花钱。分支功能做 PR 预览环境是独家体验。连接串直接塞环境变量就能用，Prisma/Drizzle 都兼容。</p>
<h3>3. 内容站 / API / 读多写少 / 全球用户 → Turso</h3>
<p>免费额度最大，边缘节点读得快。用 <code>@libsql/client</code> 接入，HTTP 协议对 Serverless 友好（没有连接池重建问题）。SQLite 方言要提前确认 ORM 兼容性。</p>
<h3>4. 已经在用 n8n / 需要 Postgres 持久化 → Neon 或 Supabase</h3>
<p>比如本站这篇<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/522/">《从零搭建 n8n：Postgres 数据库持久化配置》</a>里自建 Postgres 的场景，完全可以换成 Neon/Supabase 的免费档，省掉一台 VPS 的运维成本。</p>
<h3>选型口诀</h3>
<ul>
<li><strong>要&#8221;数据库 + 登录 + 存储&#8221;一条龙</strong> → Supabase</li>
<li><strong>要&#8221;Serverless + 分支预览 + 闲置零成本&#8221;</strong> → Neon</li>
<li><strong>要&#8221;免费额度最大 + 边缘快&#8221;</strong> → Turso</li>
<li><strong>只认 MySQL 且预算充足</strong> → PlanetScale（付费）；否则用 Turso 替代</li>
</ul>

<h2>七、FAQ</h2>
<p><strong>Q1：PlanetScale 还能白嫖吗？</strong><br />
A：不能。免费层已于 2024 年 4 月移除，现在只有付费方案。需要免费 MySQL 兼容方案可评估 Turso（SQLite 方言）或自托管。</p>
<p><strong>Q2：Supabase 和 Neon 到底怎么二选一？</strong><br />
A：想要 Auth/Storage/Realtime 一体化选 Supabase；想要 Serverless 缩容到零、数据库分支选 Neon。两者底层都是 Postgres，后期切换成本可控，也可以同时用：Supabase 做主业务库，Neon 做预览/实验库。</p>
<p><strong>Q3：Turso 免费档真的有 5GB 吗？有什么坑？</strong><br />
A：按 2026 年公开政策，免费档约 5GB 存储、约 100 个库，量级上是三家最大。但它是 SQLite（libSQL）方言，不是 Postgres；且 2026 年初调整过缩容策略，开通前请以官网 Pricing 页为准。</p>
<p><strong>Q4：毕业了学生包还能用吗？</strong><br />
A：学生身份失效后，多数权益不再延续或降为普通免费档。请在到期前迁移数据、导出配置，切勿用过期身份续期。</p>
<p><strong>Q5：非全日制 / 在职研究生能申请学生包吗？</strong><br />
A：以 GitHub 官方审核口径为准，通常在读 + 有效证明即可，具体看材料。被拒后按邮件提示补充材料重新提交，别反复撞审。</p>
<p><strong>Q6：免费数据库的数据安全吗？会被清空吗？</strong><br />
A：正常不会主动清空，但闲置暂停（Supabase）、条款变更、额度超限都可能影响可用性。免费档通常无完整自动备份，<strong>重要数据务必自己定期导出备份</strong>。</p>
<p><strong>Q7：Supabase 免费项目闲置暂停了怎么办？</strong><br />
A：登录控制台手动恢复即可。长期运行的项目建议保持最低频活跃，或升级到付费档。</p>
