<p>核心摘要（Key Takeaways）：<br />
&#8211; <strong>没有公网 IP 也能远程访问 NAS</strong>：Cloudflare Tunnel 采用反向隧道，NAS 主动向 Cloudflare 边缘建连，全程不开放家里任何入站端口，运营商大内网、光猫拨号都不是障碍。<br />
&#8211; <strong>2026 年最新配置流程</strong>：Zero Trust 控制台（one.dash.cloudflare.com）→ Networks → Tunnels → 创建 Cloudflared 隧道 → 复制 Token → NAS 上用 Docker 一行命令启动 connector → 在 Public Hostname 里绑定域名。<br />
&#8211; <strong>NAS 品牌全覆盖</strong>：群晖、威联通、极空间、绿联只要支持 Docker，就能用同一套方法；本文给出通用方案和各品牌差异点。<br />
&#8211; <strong>安全别裸奔</strong>：用 Zero Trust Access 给 NAS 管理页加一层登录认证（支持一次性验证码），避免域名被扫描到后直接暴露。</p>
<p>家里有台 NAS，存了照片、电影、文档，出门在外却访问不了——十有八九是卡在&#8221;没有公网 IP&#8221;这一步。运营商给的是大内网地址，端口转发、DDNS 全都失效；找运营商要公网 IP 越来越难，就算要到，IP 还经常变动。</p>
<p>解决办法不止一种。本站旧文<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/547/">《无公网 IP 方案：利用 Cloudflare Tunnel、Tailscale 与 Zerotier 实现远程访问》</a>横向对比了三种免费方案，建议先读它做选型；<strong>本文是那篇的升级实操篇——只讲 Cloudflare Tunnel + NAS 这个组合</strong>，把每一步都掰开讲透，照着做 30 分钟就能在公司打开家里的 NAS。</p>
<h2>一、原理一句话</h2>
<p>传统远程访问是&#8221;外网敲门进家里&#8221;（需要公网 IP + 端口转发）；Cloudflare Tunnel 反过来，是&#8221;NAS 从家里主动向 Cloudflare 打一条加密隧道&#8221;，外网访问时先到 Cloudflare 边缘，再顺着这条已建好的隧道进来。<strong>家里路由器不需要任何入站规则，公网 IP 可有可无。</strong></p>
<p>这套方案的代价：流量会经过 Cloudflare 边缘节点，且走的是 HTTPS（443 端口），适合 NAS 管理后台、相册、笔记、博客这类 Web 服务；不适合跑大流量影音串流（受 Cloudflare 服务条款限制，详见第九节）。</p>
<h2>二、准备工作（3 样东西）</h2>
<ol>
<li><strong>一个 Cloudflare 账号</strong>：免费注册即可，Tunnel 功能在免费计划里全开。</li>
<li><strong>一个托管在 Cloudflare 的域名</strong>：Tunnel 需要把子域名解析到隧道上，域名必须把 NS 换到 Cloudflare。没有域名？可以参考本站<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/221/">《GNAME 免费二级域名 eu.cc 托管 CF 教程》</a>，零成本搞定。</li>
<li><strong>一台能跑 Docker 的 NAS</strong>：群晖、威联通、极空间、绿联近年的机型都自带 Docker（群晖叫 Container Manager，威联通叫 Container Station），本文方法通用。</li>
</ol>
<blockquote><p>
  域名不强制要求备案：流量实际走的是 Cloudflare 海外边缘节点，不经过国内服务器，不涉及备案问题。
</p></blockquote>
<h2>三、步骤一：在 Zero Trust 控制台创建 Tunnel</h2>
<ol>
<li>登录 <a class="wp-editor-md-post-content-link" href="https://one.dash.cloudflare.com/">one.dash.cloudflare.com</a>（Cloudflare Zero Trust 控制台），左侧导航进入 <strong>Networks → Tunnels</strong>。</li>
<li>点击 <strong>Create a tunnel</strong>，连接器类型选择 <strong>Cloudflared</strong>，给隧道起个名字（比如 <code>home-nas</code>），点击 <strong>Save tunnel</strong>。</li>
<li>下一页会显示 connector 安装命令——<strong>我们只需要里面的 Token</strong>（一长串以 <code>eyJ</code> 开头的字符串）。复制下来妥善保存，<strong>这串 Token 就是隧道的全部凭证，泄露等于把家里大门钥匙交出去</strong>。</li>
<li>暂时不要点下一步跑安装命令，先记下这个页面，稍后在&#8221;步骤三&#8221;回来配置域名。</li>
</ol>
<blockquote><p>
  习惯命令行的老手也可以用 CLI：<code>cloudflared tunnel login</code> → <code>cloudflared tunnel create home-nas</code> → <code>cloudflared tunnel token home-nas</code>，效果和控制台完全一致。但新手建议走控制台，配置更直观。
</p></blockquote>
<h2>四、步骤二：在 NAS 上安装并运行 cloudflared</h2>
<p>cloudflared 是 Cloudflare 官方的隧道客户端。最省心的办法是 Docker，一行命令搞定，四个品牌通用。</p>
<h3>通用 Docker 命令（SSH 或各品牌 Docker 界面均可）</h3>
<pre><code class="language-bash line-numbers">docker run -d \
  --name cloudflared \
  --restart always \
  cloudflare/cloudflared:latest \
  tunnel --no-autoupdate run --token <把这里换成你的Token>
</code></pre>
<p>各品牌操作入口不同，但本质都是&#8221;新建容器 + 填镜像和启动命令&#8221;：</p>
<ul>
<li><strong>群晖（DSM 7.2+）</strong>：打开 <strong>Container Manager → 项目 → 新增</strong>，粘贴下面的 compose 文件（把 TOKEN 换成你的）：
<pre><code class="language-yaml line-numbers">services:
cloudflared:
  image: cloudflare/cloudflared:latest
  container_name: cloudflared
  command: tunnel --no-autoupdate run --token <你的Token>
  restart: always
</code></pre>
</li>
<li><strong>威联通（QTS）</strong>：Container Station → 创建容器 → 搜索 <code>cloudflare/cloudflared</code> → 在&#8221;命令&#8221;栏填 <code>tunnel --no-autoupdate run --token &lt;你的Token&gt;</code>。</li>
<li><strong>极空间 / 绿联</strong>：各自的 Docker 管理界面同样支持&#8221;自定义容器&#8221;，镜像和启动参数与上面一致。</li>
</ul>
<p>启动后回到 Zero Trust 控制台的 Tunnels 列表，隧道状态显示 <strong>Healthy</strong> 即表示 NAS 已成功连上 Cloudflare 边缘。可以用 <code>docker logs cloudflared</code> 确认日志里出现 <code>Registered tunnel connection</code>。</p>
<h2>五、步骤三：配置公网域名（Public Hostname）</h2>
<ol>
<li>在 Tunnels 列表点进你的隧道，切换到 <strong>Public Hostname</strong> 选项卡，点击 <strong>Add a public hostname</strong>。</li>
<li>填写三项：
<ul>
<li><strong>Subdomain</strong>：比如 <code>nas</code>（最终得到 <code>nas.你的域名.com</code>）；</li>
<li><strong>Domain</strong>：选择你托管在 Cloudflare 的域名；</li>
<li><strong>Service</strong>：选择 <strong>HTTP</strong>，URL 填 NAS 管理页面的内网地址和端口。</li>
</ul>
</li>
<li>端口对照表（在 NAS 浏览器登录页的地址栏里也能看到 <code>:xxxx</code>）：</li>
</ol>

<p>除了管理后台，你还可以为相册、笔记、影音等每个服务各加一条 Public Hostname，比如 <code>photo.你的域名.com</code>、<code>note.你的域名.com</code>，一个 Tunnel 带多个子域名完全免费。</p>
<h2>六、步骤四：访问测试与开机自启</h2>
<ol>
<li>在手机流量（非家里 Wi-Fi）下打开 <code>https://nas.你的域名.com</code>，能看到 NAS 登录页即成功。</li>
<li>断开重连测试：重启 NAS 或重启容器，确认隧道自动恢复。Docker 的 <code>--restart always</code>（或 compose 的 <code>restart: always</code>）已保证开机自启。</li>
<li>长期运行建议：在 Zero Trust 控制台偶尔看一眼隧道状态；cloudflared 容器建议开启自动更新或定期手动拉取新镜像。</li>
</ol>

<h2>八、安全加固：给 NAS 加一层 Access 登录保护</h2>
<p>域名一旦公开，就会被全网扫描。用 Cloudflare 的 <strong>Zero Trust Access</strong>（免费版含 50 个用户席位）给隧道加一道认证，访问 NAS 前先验证身份：</p>
<ol>
<li>Zero Trust 控制台 → <strong>Access → Applications → Add an application → Self-hosted</strong>。</li>
<li>填写应用名，Subdomain/Domain 填 <code>nas.你的域名.com</code>（与隧道 hostname 一致）。</li>
<li>创建策略（Policy）：动作为 <strong>Allow</strong>，规则选 <strong>Emails</strong> 填你自己的邮箱（或选 One-time PIN 一次性验证码，最省事）。</li>
<li>保存后再次访问域名，会先跳转到 Cloudflare 登录页，验证通过才放行到 NAS。</li>
</ol>
<p>这套组合拳下来：<strong>无入站端口 + 边缘 HTTPS + 登录前置认证</strong>，安全性远超传统端口转发。记住旧文<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/547/">《无公网 IP 方案》</a>里的原则：能放私网的别公开，必须公开的加认证。</p>
<h2>九、局限与避坑</h2>
<ul>
<li><strong>不适合大流量串流</strong>：Cloudflare 免费 Tunnel 的服务条款对&#8221;用隧道做 CDN/大文件分发&#8221;有限制。管理后台、相册浏览、文档同步这类轻量 Web 流量没问题；拿它做 4K 影音直链、PT 下载站有被限速甚至封隧道风险，重度影音需求建议走 Tailscale 这类 P2P 方案（见旧文对比）。</li>
<li><strong>速度取决于上行和边缘节点</strong>：国内访问走 Cloudflare 海外边缘，延迟比直连高，传大文件不如局域网快，这是架构代价。</li>
<li><strong>Token 是最高机密</strong>：不要截图发群、不要提交到公开 Git 仓库，泄露后立即在控制台删除隧道重建。</li>
<li><strong>NAS 本地账号也要强密码</strong>：Access 只是多一道门，NAS 自身的 admin 密码和双因素认证同样要开。</li>
</ul>

<h2>十、FAQ</h2>
<p><strong>Q1：没有公网 IP 怎么远程访问 NAS？</strong><br />
A：三种主流免费路线：① Cloudflare Tunnel（本文方案，反向隧道+域名访问，最适合 Web 服务）；② Tailscale / Zerotier（虚拟组网，像局域网一样直连设备）。三者的详细对比见本站旧文<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/547/">《无公网 IP 方案》</a>。</p>
<p><strong>Q2：Cloudflare Tunnel 完全免费吗？</strong><br />
A：是，Tunnel 本身、多个子域名、Access 基础认证都在免费计划内。免费的是&#8221;隧道&#8221;不是&#8221;无限带宽&#8221;，轻量个人使用足够。</p>
<p><strong>Q3：需要准备域名吗？可以用 IP 直接访问吗？</strong><br />
A：必须用域名，Tunnel 的访问入口就是 <code>子域名.你的域名</code>。没有域名可用免费二级域名托管到 Cloudflare（参考本站 eu.cc 教程）。</p>
<p><strong>Q4：手机 App（群晖 DS file、Qfile 等）能用 Tunnel 域名吗？</strong><br />
A：可以。这些 App 支持填写&#8221;域名 + HTTPS 端口&#8221;，填 <code>nas.你的域名.com</code>、端口 443 即可。但注意：如果开了 Access 前置认证，App 内登录会被拦截，这种情况建议给 App 单独配一个不加 Access 策略的子域名。</p>
<p><strong>Q5：和群晖 QuickConnect / 威联通 myQNAPcloud 比哪个好？</strong><br />
A：官方中转方案开箱即用但速度看运气、且依赖厂商服务器；Tunnel 给你独立域名+HTTPS+自定义认证，速度和自主性更好，代价是需要自己动手配置一次。</p>
<p><strong>Q6：访问速度慢怎么办？</strong><br />
A：先确认是上行带宽瓶颈还是边缘节点问题：局域网内直连 IP 如果很快，那就是隧道链路问题，属正常代价；如果局域网也慢，先优化 NAS 本身。日常管理、看照片完全够用，别指望它跑满千兆。</p>
<p><strong>Q7：隧道突然连不上了怎么排查？</strong><br />
A：三步：① NAS 上 <code>docker logs cloudflared</code> 看是否还在运行；② Zero Trust 控制台看隧道状态是否为 Healthy；③ 检查家里网络是否断网。九成问题是容器没自启或 Token 被误删。</p>
<p><strong>Q8：旧文 547 和这篇是什么关系？</strong><br />
A：<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/547/">旧文 547</a>是&#8221;选型篇&#8221;，对比 Cloudflare Tunnel、Tailscale、Zerotier 三种方案帮你做决定；本文是&#8221;实操篇&#8221;，只聚焦 Cloudflare Tunnel + NAS，把配置走完。两篇配合阅读，先选型、再动手。</p>
<h2>总结</h2>
<p>没有公网 IP，不是远程访问 NAS 的终点。Cloudflare Tunnel 用一条&#8221;由内向外&#8221;的加密隧道绕开了所有 NAT 和端口限制：控制台建隧道、NAS 上跑一个 Docker 容器、绑个子域名，30 分钟就能实现 <code>https://nas.你的域名.com</code> 全球可达。再叠一层 Zero Trust Access 认证，安全性和易用性兼得。</p>
<p>动手前最后核对清单：Cloudflare 账号 ✅、托管好的域名 ✅、NAS 上的 cloudflared 容器状态 Healthy ✅、手机流量下能打开登录页 ✅。祝折腾愉快。</p>
