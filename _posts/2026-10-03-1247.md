<p>核心摘要（Key Takeaways）：<br />
&#8211; <strong>免费额度实在</strong>：Cloudflare Pages 免费档提供无限流量请求、每月约 500 次构建、免费自定义域名与自动 HTTPS，个人博客完全零成本运行（具体额度以官网为准）。<br />
&#8211; <strong>极简流水线</strong>：本地 Hugo/Hexo 生成静态页面 → 推送 GitHub → Pages 自动构建部署 → 绑定域名，更新文章只需一次 <code>git push</code>。<br />
&#8211; <strong>关键配置一次搞定</strong>：Hugo 用框架预设（构建命令 <code>hugo --gc --minify</code>，输出目录 <code>public</code>），版本不对齐就加 <code>HUGO_VERSION</code> 环境变量；Hexo 用 <code>hexo generate</code>，新版 Node 记得配 <code>NODE_VERSION</code>。<br />
&#8211; <strong>零成本全家桶</strong>：静态托管用 Pages，图床可叠加 Cloudflare R2（见<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/546/">免费图床搭建方案</a>），一套组合拳把建站成本打到 0。</p>
<p>建个人博客，最劝退的三件事是：<strong>服务器贵、备案麻烦、维护累</strong>。租一台云服务器一年几百块，备案动不动等一两周，还要操心系统更新、SSL 证书续期、被挖矿木马攻陷——写了几篇博客，人却先成了运维。</p>
<p>其实 2026 年还有更简单的路：用 <strong>Cloudflare Pages + Hugo/Hexo</strong>。静态页面没有服务器要养，没有数据库要备份；每次写完文章推一下 Git，Cloudflare 自动构建、全球 CDN 分发，HTTPS 自动签发。本文是一篇手把手的 Cloudflare教程，从环境准备到域名绑定全流程讲透。</p>

<h2>一、方案总览：Pages + Hugo/Hexo 是怎么工作的</h2>
<p>先看整体架构，理解之后每一步都不会懵：</p>
<pre><code class="line-numbers">┌──────────────┐     Markdown 文章
│  本地写作     ├──────────────────┐
└──────────────┘                    ▼
                          ┌──────────────────┐
                          │ Hugo / Hexo      │
                          │ 本地生成静态 HTML │
                          └────────┬─────────┘
                                   │  git push
                                   ▼
                          ┌──────────────────┐
                          │ GitHub 仓库       │
                          │ (可私有仓库)      │
                          └────────┬─────────┘
                                   │  Webhook 触发
                                   ▼
                          ┌──────────────────┐
                          │ Cloudflare Pages  │
                          │ 云端自动构建部署   │
                          └────────┬─────────┘
                                   │  全球 300+ 边缘节点分发
                                   ▼
                 xxx.pages.dev 子域名 / 自定义域名 + 自动 HTTPS
</code></pre>
<p>核心逻辑：<strong>你的电脑只负责&#8221;写文章、生成页面&#8221;；GitHub 只负责&#8221;存代码&#8221;；部署、CDN、HTTPS 全是 Cloudflare 的事</strong>。这意味着三点好处：</p>
<ol>
<li><strong>免运维</strong>：没有服务器，没有 SSH，没有补丁。</li>
<li><strong>全球加速</strong>：Cloudflare 在全球有 300+ 边缘节点，访客就近访问。</li>
<li><strong>免费</strong>：静态资源请求不限量、不限流量，免费档对个人博客几乎无上限。</li>
</ol>
<p>需要动态功能（评论、后端 API）？静态托管本身不支持，但可以用 <a class="wp-editor-md-post-content-link" href="https://waynetalk.com/547/">Cloudflare Tunnel 把家里 NAS 的服务暴露出来</a>，或后续加 Workers 函数，这就是进阶玩法了。</p>

<h2>三、步骤 1：本地生成博客</h2>
<h3>3.1 Hugo 版</h3>
<pre><code class="language-bash line-numbers"># 安装 Hugo（以 macOS / Linux 为例，Windows 可去官网下载 exe）
brew install hugo          # macOS
# 或：sudo apt install hugo  # Ubuntu/Debian

# 新建站点
hugo new site myblog && cd myblog
git init
# 安装一个主题（示例用 PaperMod，可自行替换）
git submodule add https://github.com/adityatelange/hugo-PaperMod.git themes/PaperMod
echo "theme = 'PaperMod'" >> hugo.toml

# 写第一篇文章并本地预览
hugo new posts/hello.md
hugo server -D
</code></pre>
<p>浏览器打开 <code>http://localhost:1313</code> 就能看到效果。满意后执行 <code>hugo --gc --minify</code> 生成 <code>public/</code> 目录，确认构建没报错。</p>
<h3>3.2 Hexo 版</h3>
<pre><code class="language-bash line-numbers"># 先装 Node.js（建议 LTS 版本），再装 Hexo
npm install -g hexo-cli
hexo init myblog && cd myblog
npm install

# 写第一篇文章并本地预览
hexo new "我的第一篇文章"
hexo server
</code></pre>
<p>浏览器打开 <code>http://localhost:4000</code> 预览。确认无误后 <code>hexo generate</code> 会在 <code>public/</code> 目录生成静态文件。</p>
<blockquote><p>
  💡 习惯：<strong>永远先在本地预览确认无误，再推送到线上</strong>，能省掉一半构建失败的排查时间。
</p></blockquote>
<h2>四、步骤 2：推送代码到 GitHub</h2>
<pre><code class="language-bash line-numbers">cd myblog
# 忽略构建产物（由 Cloudflare 云端生成，不必进仓库）
echo "public/" >> .gitignore

git add -A
git commit -m "init: my blog"
git remote add origin git@github.com:你的用户名/你的仓库名.git
git branch -M main
git push -u origin main
</code></pre>
<p>推送后仓库里应该只有<strong>源码</strong>（Markdown 文章、主题、配置文件），没有 <code>public/</code> 目录。</p>

<h3>常见坑：Hugo 构建失败</h3>
<p>90% 的 Hugo 构建失败都是<strong>版本问题</strong>：Cloudflare 默认的 Hugo 版本较旧，不支持新版主题语法。修复方法：</p>
<ol>
<li>在 Pages 项目 → <strong>设置 → 环境变量</strong>，添加：
<ul>
<li>变量名：<code>HUGO_VERSION</code></li>
<li>值：和你本地 <code>hugo version</code> 一致的版本号（如 <code>0.147.7</code>）</li>
</ul>
</li>
<li>回到<strong>部署</strong>页，点击失败记录旁的三个点 → <strong>重试部署</strong>。</li>
</ol>
<p>Hexo 用户则注意两点：确认 <code>package.json</code> 和 <code>package-lock.json</code> 都提交到了仓库；如果构建日志报 Node 版本问题，在环境变量里加 <code>NODE_VERSION</code>（如 <code>20</code>）。</p>
<h2>六、步骤 4：绑定自定义域名 + 开启 HTTPS</h2>
<ol>
<li>在 Pages 项目中进入 <strong>自定义域 → 设置自定义域</strong>，输入你的域名（如 <code>blog.example.com</code>）。</li>
<li><strong>域名 DNS 已托管在 Cloudflare</strong>：自动创建 DNS 记录、自动签发 SSL 证书，通常几十秒生效。</li>
<li><strong>域名在其他服务商</strong>：按页面提示，在域名商处添加一条 CNAME 记录指向 <code>你的项目名.pages.dev</code> 即可，SSL 同样自动签发。</li>
<li>之后所有访问自动跳转 HTTPS，无需手动续期证书。</li>
</ol>
<p>想了解更多 Cloudflare 在国内外的玩法（比如用自有域名做其他服务），可以看看站内的<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/547/">无公网 IP 远程访问方案</a>，同属 Cloudflare 生态的免费利器。</p>

<p><strong>Q3：Hugo 和 Hexo 到底选哪个？</strong><br />
A：中文内容多、想用丰富主题和插件 → Hexo；讨厌装环境、追求构建速度 → Hugo。两者在 Pages 上的部署成本几乎一样，随时可以换。</p>
<p><strong>Q4：可以用私有 GitHub 仓库吗？</strong><br />
A：可以。授权时给 Cloudflare 读取权限即可，构建触发通过 Webhook，代码不会公开。</p>
<p><strong>Q5：国内访问速度怎么样？需要备案吗？</strong><br />
A：Cloudflare 是海外节点，国内访问速度取决于跨境线路，通常可用但不如国内厂商快。不走国内服务器所以<strong>无需备案</strong>；如果主要读者在国内且追求极速，可考虑国内静态托管做分流。</p>
<p><strong>Q6：<code>pages.dev</code> 域名打不开怎么办？</strong><br />
A：部分网络环境下 <code>pages.dev</code> 可能访问不稳定，绑定自己的自定义域名即可解决，见第六节。</p>
<p><strong>Q7：文章里的图片存哪里？</strong><br />
A：推荐 Cloudflare R2 免费对象存储 + PicGo 上传，<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/546/">详细教程见这篇</a>。别把图片直接塞 Git 仓库，仓库会迅速膨胀。</p>
<p><strong>Q8：以后想加动态功能（评论、API）怎么办？</strong><br />
A：静态托管只负责&#8221;页面&#8221;。评论用 Giscus/Waline 纯前端方案；需要后端逻辑可以加 Cloudflare Workers，或用 <a class="wp-editor-md-post-content-link" href="https://waynetalk.com/547/">Cloudflare Tunnel 把家里 NAS 的服务安全暴露出来</a>。</p>
