<p>核心摘要（Key Takeaways）：<br />
&#8211; <strong>自建路线 = VPS 跑 Xray（VLESS + Reality）做节点 + 家里 OpenWrt 软路由做透明网关</strong>，一次配置、全屋设备自动走代理，不再逐台装客户端。<br />
&#8211; <strong>VLESS + Reality 是当前主流的自建组合</strong>：无需购买域名和证书，借用真实大厂站点的 TLS 指纹做伪装，能把主动探测&#8221;回落&#8221;到真实目标站，抗封锁能力强，搭配 <code>xtls-rprx-vision</code> 流控传输效率高。<br />
&#8211; <strong>服务端搭建只需五步</strong>：准备 VPS → 安装 Xray → 生成 UUID / x25519 密钥对 / Short ID → 编写 <code>config.json</code> → 开放防火墙端口并启动服务。<br />
&#8211; <strong>软路由两种姿势</strong>：直接做主路由跑 TUN 透明代理（mihomo / sing-box），或保持原主路由不动、把软路由当&#8221;旁路由网关&#8221;；核心是做好 DNS 分流和内网回环规则。</p>
<p>买的订阅高峰期卡顿、IP 时不时被风控、流量用着不放心——这是很多人的真实痛点。自建节点的思路恰好反过来：线路自己搭、出口自己管，延迟和稳定性完全取决于你选的机房和线路；再配上一台 OpenWrt 软路由做家里的透明代理网关，手机、电脑、电视、游戏机连上 WiFi 就自动走代理，分流规则统一维护。这篇文章把这条链路从头到尾讲透：<strong>服务端用 Xray 部署 VLESS + Reality，网关端用 OpenWrt 实现透明代理</strong>，纯技术实战，不带任何商家链接。</p>

<h2>二、准备工作</h2>
<ol>
<li><strong>一台海外 VPS</strong>：1 vCPU / 1 GB 内存起步即可，Xray 资源占用很低；流量按实际用量选。系统推荐 Ubuntu 22.04 LTS 或 Debian 12（64 位）。</li>
<li><strong>一台软路由</strong>（网关端用）：x86_64 或 ARM64 架构，内存建议 512MB 以上，已刷好 OpenWrt。普通路由器刷机前先确认型号支持。</li>
<li><strong>端口规划</strong>：服务端建议用 443 端口（最像正常 HTTPS 流量）；云厂商安全组和系统防火墙都要放行该端口。</li>
<li><strong>SSH 工具</strong>：任意终端即可，服务端全程命令行操作。</li>
</ol>

<h2>三、服务端搭建：VPS 上部署 Xray（VLESS + Reality）</h2>
<h3>步骤 1：安装 Xray</h3>
<p>SSH 登录 VPS（建议 root 用户），先更新系统并安装基础依赖，然后用 Xray 官方安装脚本一键安装：</p>
<pre><code class="language-bash line-numbers">apt update && apt install -y curl wget tar jq openssl

# Xray 官方安装脚本（项目：XTLS/Xray-install）
bash -c "$(curl -L https://github.com/XTLS/Xray-install/raw/main/install-release.sh)" @ install
</code></pre>
<p>安装完成后，Xray 会被注册为系统服务，主配置文件位于 <code>/usr/local/etc/xray/config.json</code>。</p>
<h3>步骤 2：生成三要素（UUID、密钥对、Short ID）</h3>
<p>VLESS + Reality 需要三组参数，依次执行生成并<strong>妥善记录</strong>：</p>
<pre><code class="language-bash line-numbers"># 1. 用户 UUID
xray uuid

# 2. Reality x25519 密钥对（输出 Private key 和 Public key）
xray x25519

# 3. Short ID（16 位十六进制，长度为 2 的倍数）
openssl rand -hex 8
</code></pre>
<blockquote><p>
  ⚠️ <strong>私钥（Private key）只放在服务端配置文件里，切勿泄露；公钥（Public key）给客户端用。</strong>
</p></blockquote>
<h3>步骤 3：编写服务端配置文件</h3>
<p>编辑 <code>/usr/local/etc/xray/config.json</code>，写入如下配置（把占位符换成你上一步生成的值）：</p>
<pre><code class="language-json line-numbers">{
  "log": { "loglevel": "warning" },
  "inbounds": [{
    "port": 443,
    "protocol": "vless",
    "settings": {
      "clients": [{
        "id": "你的UUID",
        "flow": "xtls-rprx-vision"
      }],
      "decryption": "none"
    },
    "streamSettings": {
      "network": "tcp",
      "security": "reality",
      "realitySettings": {
        "dest": "www.microsoft.com:443",
        "serverNames": ["www.microsoft.com"],
        "privateKey": "你的私钥",
        "shortIds": ["你的ShortID"]
      }
    },
    "sniffing": {
      "enabled": true,
      "destOverride": ["http", "tls", "quic"]
    }
  }],
  "outbounds": [{ "protocol": "freedom", "tag": "direct" }]
}
</code></pre>
<p>几个关键字段的含义：</p>
<ul>
<li><strong><code>dest</code> / <code>serverNames</code></strong>：Reality 的伪装目标——一个真实存在、支持 TLSv1.3 的大厂站点。客户端握手时 SNI 指向它，服务端用自己的私钥完成&#8221;偷梁换柱&#8221;；非授权的探测流量会被<strong>回落</strong>到真实目标站，从而骗过主动探测。</li>
<li><strong><code>flow: xtls-rprx-vision</code></strong>：目前 VLESS 最成熟的流控，去除了明显的 TLS in TLS 特征，传输效率高。</li>
<li><strong><code>sniffing</code></strong>：流量嗅探，用于后续分流规则按域名识别，软路由/客户端做分流时依赖它。</li>
</ul>
<p>校验配置文件语法无误（<code>xray -test -config /usr/local/etc/xray/config.json</code>），有报错先排查 JSON 格式。</p>
<h3>步骤 4：放行防火墙端口</h3>
<pre><code class="language-bash line-numbers"># 系统防火墙（Ubuntu/Debian 示例）
ufw allow 443/tcp
ufw enable
</code></pre>
<p>同时记得在云厂商控制台的安全组里放行 443/TCP。如果 443 被占用，可换成其他高位端口，只是隐蔽性略降。</p>
<h3>步骤 5：启动服务并开启 BBR</h3>
<pre><code class="language-bash line-numbers">systemctl enable xray
systemctl start xray
systemctl status xray   # 确认 active (running)

# 开启 BBR 拥塞控制，提升弱网/丢包环境下的吞吐
echo "net.core.default_qdisc=fq" >> /etc/sysctl.conf
echo "net.ipv4.tcp_congestion_control=bbr" >> /etc/sysctl.conf
sysctl -p
</code></pre>
<p>到这里服务端就绪。记下这套连接信息：<strong>服务器 IP、端口、UUID、公钥、Short ID、SNI（serverNames）</strong>，下一步客户端要用。</p>
<h2>四、客户端配置：先单设备跑通</h2>
<p>在折腾软路由之前，强烈建议先在电脑或手机上把节点跑通，确认服务端没问题。</p>
<ul>
<li><strong>Windows / macOS</strong>：<a class="wp-editor-md-post-content-link" href="https://github.com/clash-verge-rev/clash-verge-rev">Clash Verge Rev</a>（mihomo 内核），或 v2rayN / sing-box 桌面版。</li>
<li><strong>Android</strong>：NekoBox、sing-box 安卓版；<strong>iOS</strong>：Shadowrocket、Streisand、sing-box iOS 版。</li>
</ul>
<p>以 Clash（mihomo 内核）为例，代理节点写法如下：</p>
<pre><code class="language-yaml line-numbers">proxies:
  - name: "自建-VLESS-Reality"
    type: vless
    server: 你的服务器IP
    port: 443
    uuid: 你的UUID
    udp: true
    tls: true
    flow: xtls-rprx-vision
    servername: www.microsoft.com
    reality-opts:
      public-key: 你的公钥
      short-id: 你的ShortID
    client-fingerprint: chrome
</code></pre>
<blockquote><p>
  📖 Clash 全平台的详细配置方法见站内：<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/702/">Clash Verge Rev 现代化全平台配置指南</a>；想用新一代 sing-box 内核的看这篇：<a class="wp-editor-md-post-content-link" href="https://waynetalk.com/701/">Sing-box 新一代通用代理核心从入门到精通</a>。
</p></blockquote>
<p>连通性验证：先直连 ping 一下服务器 IP 确认网络可达，再在客户端里测节点延迟，能正常打开境外网站即服务端 OK。<strong>最常见的报错是 reality 握手失败</strong>，九成是公钥/私钥配反、Short ID 对不上或 SNI 写错，逐项核对即可。</p>

<h3>5.2 安装代理内核</h3>
<p>OpenWrt 上两种主流选择：</p>
<ol>
<li><strong>mihomo（原 Clash Meta）</strong>：opkg 软件源或第三方源安装，YAML 配置，上手快，规则生态成熟。</li>
<li><strong>sing-box</strong>：JSON 配置，TUN 模式体验好，官方 ipk 安装：<code>opkg update &amp;&amp; opkg install sing-box</code>（部分源需先添加）。</li>
</ol>
<p>二选一即可，不要同时跑两套透明代理，会互相抢流量。</p>
<h3>5.3 TUN 透明代理最小配置（sing-box 示例）</h3>
<p>TUN 模式的原理是在软路由上建一张虚拟网卡，把全屋流量&#8221;吸&#8221;进来再按规则分流。最小可用配置抓住这几块：</p>
<pre><code class="language-json line-numbers">{
  "inbounds": [{
    "type": "tun",
    "tag": "tun-in",
    "address": "172.16.250.1/30",
    "auto_route": true,
    "strict_route": true
  }],
  "outbounds": [
    { "type": "vless", "tag": "自建节点", "...": "填入第四节的节点参数" },
    { "type": "direct", "tag": "direct" }
  ],
  "route": {
    "rules": [
      { "ip_is_private": true, "outbound": "direct" },
      { "rule_set": "geosite-cn", "outbound": "direct" },
      { "rule_set": "geoip-cn", "outbound": "direct" }
    ],
    "final": "自建节点"
  }
}
</code></pre>
<p>注意两点：TUN 地址避开 Docker 默认网段（<code>172.17.0.0/16</code> 等），否则装了 Docker 的软路由会冲突；第一条 <code>ip_is_private → direct</code> 必不可少，否则局域网流量会被送进代理造成回环。</p>
<h3>5.4 DNS 分流：防泄漏也防污染</h3>
<p>透明代理最容易翻车的是 DNS：</p>
<ul>
<li><strong>国内域名</strong> → 用国内 DNS（如 223.5.5.5）直连解析，速度快；</li>
<li><strong>国外域名</strong> → 走代理通道向境外公共 DNS 发起解析，拿到无污染结果；</li>
<li><strong>路由只看真实 IP</strong>：即使某域名不在国内域名表里，只要解析出的 IP 归属国内，依然走直连，避免无效绕行。</li>
</ul>
<p>sing-box / mihomo 都支持按规则集分 DNS，配好后用 DNS 泄漏测试确认没有本地域名解析走出代理。</p>
<h2>六、安全与维护：节点能用久的关键</h2>
<ol>
<li><strong>密钥即资产</strong>：私钥、UUID 只存服务端和自己的客户端，定期更换 UUID 和 Reality 密钥对，旧密钥及时作废。</li>
<li><strong>最小化暴露面</strong>：服务器防火墙只开放代理端口和 SSH；如需用可视化面板，务必设强密码并限制来源 IP，不要裸奔在公网。</li>
<li><strong>保持内核更新</strong>：Xray、mihomo、sing-box 都有活跃的安全更新，定期 <code>opkg upgrade</code> / 重跑安装脚本跟进大版本。</li>
<li><strong>备份配置</strong>：服务端 <code>config.json</code> 和软路由配置各存一份离线备份，重装机器时 5 分钟恢复。</li>
<li><strong>监控与限流</strong>：装个简单的流量统计，异常跑量第一时间能发现；多用户共享时给每个客户端独立 UUID，方便单独吊销。</li>
</ol>

<h2>七、FAQ</h2>
<p><strong>Q1：VLESS + Reality 还需要买域名、申请证书吗？</strong><br />
不需要，这是 Reality 最大的便利之处。它借用真实大厂站点的 TLS 握手指纹完成伪装，证书和 SNI 都是&#8221;借&#8221;来的，省掉了域名购买、续费和证书维护的全套工作。</p>
<p><strong>Q2：443 端口被占用或被封怎么办？</strong><br />
换成任意高位端口（如 8443、2053 等）即可，客户端同步改端口。隐蔽性略低于 443，但功能完全正常；记得安全组和防火墙同步放行。</p>
<p><strong>Q3：客户端提示 reality 握手/校验失败怎么排查？</strong><br />
按这个顺序检查：① 公钥和私钥是否配反（服务端填私钥、客户端填公钥）；② Short ID 与服务端 <code>shortIds</code> 是否一致；③ 客户端 <code>servername</code> 是否在服务端 <code>serverNames</code> 列表里；④ 服务器时间是否准确（TLS 握手对时间敏感）。</p>
<p><strong>Q4：家里设备多，是每台装客户端好还是软路由好？</strong><br />
设备多、类型杂（电视、平板、IoT）选软路由透明代理，一处配置全网生效；经常外出、只在手机电脑上用，客户端直连更轻量。两者用的是同一套节点订阅，可以并存。</p>
<p><strong>Q5：自建节点和买订阅相比，优缺点是什么？</strong><br />
自建的优点是线路可控、隐私自主、长期成本低；缺点是需要自己动手搭和维护，出了问题没人兜底。订阅省心但质量参差。技术爱好者建议自建一条做主力，这是本文的路线。</p>
<p><strong>Q6：软路由跑透明代理会影响国内网站速度吗？</strong><br />
配置正确的分流规则下不会。国内域名/IP 走 direct 直连，代理只处理需要它的流量；TUN 本身的开销在现代软路由硬件上可以忽略。感觉变慢先检查规则是否把国内流量误送进了代理。</p>
<p><strong>Q7：Reality 的 <code>dest</code> 目标站可以随便选吗？</strong><br />
有讲究：选国外大站、支持 TLSv1.3、域名本身不做跳转的站点，稳定性最好。选好后不要频繁更换，<code>serverNames</code> 保持与 <code>dest</code> 一致。</p>
<h2>八、总结</h2>
